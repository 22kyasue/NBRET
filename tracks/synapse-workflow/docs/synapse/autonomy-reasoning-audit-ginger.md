## Conclusion and current scope

**The missing capability is the operational connection between general reasoning, observations, constrained actions and independently checked consequences.** We already have useful reasoning methods, a model-driven external engine, coding sessions capable of reasoning, typed local execution, durable histories, critique/effect-check patterns and reporting. The local rehearsal does not connect those into autonomous investigation of an unfamiliar website. Buying or adopting another framework would not by itself close that gap.

The smallest useful architecture is one investigator/controller using an existing admitted reasoning session, a separate policy/execution adapter, the existing journal/casebook, targeted research retrieval, and a visible event projection. Keep the reasoning backend replaceable. Neither ARTEX, a particular CLI, Synapse CE, nor a multi-agent configuration has won an actual matched comparison here. Starting with one investigator reduces integration variables; it is an implementation experiment, not a claim that one agent is optimal.

## ARTEX: real reasoning assets and transfer hazards

### The useful reasoning structure

At the pinned source, `agent/planner.go:19–46` describes an event-driven planner with shared per-task todo state; trigger events represent worker completion, findings and human goal/hint changes. `247–292` obtains worker conclusions, marks truncation, and prefetches graph state. The default planning procedure at `298–340` uses goal/fact/intent lineage, deeper detail on demand, duplicate avoidance, dependency sequencing and different dispositions for completed/incomplete work. It batches up to four proposed intents. [Pinned planner source](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/agent/planner.go#L247-L340).

Useful concepts to reuse: an explicit observed frontier; parent evidence for each hypothesis; persistent pending dependencies; replan after a material observation; preserve contrary evidence; retrieve full artifacts when previews are inadequate. This is more capable in principle than a fixed menu. It is not evidence that its chosen actions discover more real flaws.

### Do not import its persistence incentives unchanged

The default template `303–329` requires at least one new intent when goals remain unmet and no open/running intent exists. It allows blocked/exhausted directions to resume or be reissued after trace inspection. Those instructions can be sensible for recoverable infrastructure failures, but conflict with our explicit **security-blocked action stays stopped, no equivalent retry/reroute through another tool/session** boundary. They also risk endless work if the task incorrectly demands a vulnerability on a secure target. The same prompt has useful duplicate/diversity controls; this is not a claim that it universally ignores stops. Our adapter must classify security denial separately, persist it outside the model and allow an honest no-finding completion. [planner.go:303–340](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/agent/planner.go#L303-L340).

The narrative says the planner is not an executor, yet `375–377` appends SDK default tools and `412–427` configures bypass permissions and WebFetch. Its template even permits limited initial probes. Worker execution similarly has actual SDK tools, a working directory, model context and hooks. Planning/execution separation here is partly instruction and role design, not a proof the planner lacks execution authority. [planner.go:375–427](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/agent/planner.go#L375-L427), [worker.go:359–473](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/agent/worker.go#L359-L473).

## The bridge and existing sessions: two different connection paths

The bridge is an implemented alternative for obtaining structured reasoning, not a new source of security intelligence. `protocol.mjs:58–100` accepts text history and tool definitions, serializes them into one prompt and validates returned tool names/argument objects against a bounded JSON Schema subset. `server.mjs:5–22,50–104` authenticates loopback requests, queues one call per provider with four waiting, enforces request/output limits and returns buffered completion/SSE-shaped output. It does not translate image content or provide live token streaming. [Local protocol](../../../../references/artex/fdfb7a17-local-cli/source/tools/local-cli-bridge/protocol.mjs), [server](../../../../references/artex/fdfb7a17-local-cli/source/tools/local-cli-bridge/server.mjs).

`runner.mjs:16–26` filters selected provider environment variables while retaining other parent environment; `39–71` supplies restrictive Claude/Codex CLI flags; `73–153` starts a hidden child, writes the prompt, collects output and validates normalized results. Each decision starts a process. Actual installed CLI flag support, authentication/usage entitlement, schema compatibility and descendant cleanup remain untested. A provider call's return is not evidence its proposed ARTEX action ran. Post-completion rejection of a native-tool event cannot undo effects that may already have occurred. [Local runner](../../../../references/artex/fdfb7a17-local-cli/source/tools/local-cli-bridge/runner.mjs).

That gives two realistic candidates for a later operational comparison:

## Put research into the next decision, rather than into a giant prompt

“Use all research” should mean **every material decision can find and apply relevant evidence, corrections and limits**. It should not mean every tool is executed or all study text is supplied on every turn. The register has retrieval/citation infrastructure, not measured optimal investigator strategy.

A minimum next-action record should link:

1. The current question and applicable authoritative rule, or explicit rule uncertainty.
2. Current observations with identity/context, target/version, completeness and provenance.
3. A small number of genuinely different hypotheses, including benign explanations and preventing controls.
4. Relevant register/study passages and corrections; distinguish supported method from untested analogy.
5. The proposed smallest permitted action, prerequisites, expected discriminating observation, negative/legitimate control, and resource/effect cost.
6. Gate outcome; actual execution and observation; hypothesis disposition; outstanding uncertainty and stopping reason.

Rank candidates first by admission and required prerequisites, then by expected ability to resolve the current uncertainty, useful coverage, cost and consequences. The ranking is initially an explicit heuristic to measure; do not invent a calibrated “information gain” or risk percentage. Prefer one discriminating observation over repeated paraphrases of the same theory. If a screenshot or response is truncated, retrieve permitted complete evidence or mark the claim incomplete; a preview cannot silently become a full-source conclusion.

The following routing makes the existing corpus operational without pretending every domain applies to every target:

| Research area | Contribution to a decision | When to defer |
| --- | --- | --- |
| Service delivery, standards, commercial | Define question/scope/evidence, completion, matched comparisons and what claims a report may make | Pricing/vendor counts do not choose the next technical action or establish demand |
| Providers, defensive response | Provider inference/data boundaries; distinct action authority and response effects | Do not add MDR/EDR/cloud authority to a public-web task |
| Agent runtime, workers/queues, crawling load | Typed actions, external gates, retry/lease/effect distinction, aggregate target budgets and observed stop | Source reading of queue internals does not establish LLM swarm reasoning or a deployed sandbox |
| Authorization, evidence handling, reporting | Preserve principal/session/object/state and actual consequence; retain raw provenance plus redaction/unknown states | No authenticated roles or business objects may be assumed from a generic landing page |
| Scanners, interception proxy, network discovery | Choose observations appropriate to the question and retain configured coverage/limits; recheck discovered destinations | Do not activate scanners, expand hosts or alter proxy/CA/network state just because sources exist |
| Cloud, identity/AD | Models, collection completeness, caller/subject and effective-permission reasoning | No cloud/AD target or credentials are available in the current public-site scope |
| AI evaluation and safety | Audit scorers, separate text from effects, protect holdouts, keep denied actions stopped | Benchmark controls do not themselves authorize target actions or make a familiar exercise blind |

Specific useful method lessons and their limits:

- `ai-evaluation.takumi-pipeline-and-coverage-scope`: enumerate features, hypothesize, reproduce, verify; selected feature-map coverage is not whole-site assurance. The opened [study:51–61](../research/cybersecurity-firms/gmo-flatt-security.md) explicitly says deterministic verifiers are documented, not source-inspected, and the vendor's scanner generalizations are marketing. Reuse stage separation without inheriting its effectiveness claims.
- Cloudflare's source-audit method asks for the strongest preventing control, a concrete boundary failure, explicit missing fact and fresh adversarial review. Adapt that question discipline to browser/network observations. A source-line schema cannot be honestly satisfied with inaccessible server code; validators certify declared shape, not effect truth. See [review](../research/security-landscape/repository-reviews-20261021/cloudflare-review-thistle.md).
- `service-delivery.tool-role-evidence-limits`: the opened [toolchain guide:3–15](../research/toolchain/read-first.md) maps a question to an observation and a remaining oracle. This prevents picking a tool merely because it is fashionable or catalogued.
- `ai-evaluation.provider-adapters-lose-evidence`: [AgentDojo study:238–248](../research/assessment-evidence/deep-agentdojo.md) shows adapter transformations can turn provider blocks/errors into empty output and lose content. Preserve native error/status metadata under appropriate access controls; do not treat “no action” as a rational finish without knowing whether normalization failed.
- `ai-evaluation.skipped-detectors-are-unattempted`: [garak study:41–55](../research/assessment-evidence/deep-garak.md) distinguishes unscored search branches from resistant targets. Unknown, skipped, blocked and unavailable branches stay in the frontier/coverage ledger; never convert absence of score to proof of safety.
- `safety.capability-gate-outside-model`: [executable claims:23–25](../research/assessment-evidence/executable-claims.md) establishes selected synthetic gate decisions, explicitly not an OS sandbox. Put scope checks in actual tools and separately verify every route; model agreement is not enforcement.
- `ai-evaluation.audit-evaluator-before-tester`: [framework:75–92](../research/assessment-evidence/framework.md) is a draft protocol grounded in concrete counterexamples, not a validated standard. Mutation-test actor/object/novelty/error/completeness and verify the assertion was reached before comparing investigators.
- Autoresearch contributes a baseline, bounded candidate change and retained keep/reject rationale. Its editable model/printed loss, repeated public validation and incomplete failure retention are limits, not evidence of cheating. Use protected independent scoring and all-attempt history for method promotion, rather than copying its trust model.

## Minimal operational architecture

```text
Owner scope + budgets + stop rules
                |
Current observation/evidence store <--- constrained browser/API collector
                |                                  ^
Relevant research + corrections                     |
                |                                  |
Investigator proposes typed next action ---> policy/executor
                |                           (authority outside model)
                v                                  |
Decision/frontier journal <--- result, completeness, block, effect
                |
Independent challenge / effect-specific adjudication
                |
Read-only monitoring projection + canonical report
```

The investigator can reason autonomously within one admitted boundary and receive human steering. A page, tool result or retrieved document is untrusted observation data, not permission to alter scope, permissions or evaluation. A security-denied action and its equivalents remain recorded as stopped across restart/handoff; changing payload, tool or session must not become an evasion of that decision. Other permitted branches may continue.

The collector must supply enough sanitized, inspectable material for reasoning: accessible labels/links, rendered-state evidence when required, requests/responses within scope, limitations and session bindings. Keep credentials in a separate short-lived channel. Do not hand the planner unrestricted replayable credentials in every transcript, or claim a redacted body proves absent content. The current raw-body accessor is a local ephemeral mechanism, not a general retention/DLP policy.

For `tobirastudio.com`, the first frontier is public observations: what same-origin pages and visible interactions actually exist, which links leave scope, and which questions the observed material raises. Do not start from the practice app's order-read hypothesis. If the site has a contact form, rendering/inspecting it and submitting it are different effects. Current authorization excludes submission; record that boundary. An external asset or redirect can be catalogued from an observed URL without fetching its destination. Browser subresources may themselves leave the admitted host; the browser-execution owner must explicitly reconcile the allowed rendering model and third-party requests rather than hiding that expansion behind “read-only.” This audit makes no claim about the site's actual resources.

A useful research question can yield no material security finding. Header absence, a library fingerprint, source-visible route or a model's confident explanation does not by itself demonstrate a level-3 consequence. If confirming a hypothesis requires a form send, account or third-party destination outside the new scope, retain an owner-action requirement with the exact proposed effect instead of proceeding.

Do not build a second independent reporting or memory platform. Extend the existing journal with a narrow generic observation/decision projection and keep the canonical reader's findings/owner actions/leads. Generalizing `measurement.structuredFact` requires explicit supported schemas: today it recognizes only practice page/profile/order/transition facts. It will otherwise label legitimate new website observations unknown. Changing that projector must be versioned so an apparent novelty gain cannot be produced merely by accepting more prose.

### What the live UI should show

Show the operator-facing decision record, not hidden chain-of-thought: current question, short rationale, research source/strength, cited observation, proposed next action, gate decision, actual started/completed/failed state, consequence/unknown and remaining frontier. Distinguish model-proposed, admitted, executing, observed, reproduced, reviewed and independently verified. No percent “site secure” or generic “research complete” gauge should be derived from visited URLs or stage count.

Events need monotonic sequence IDs, run/generation, producer, timestamp and links to retained artifacts. Connection loss should display stale/unknown and last event time. A replay should retain its saved timestamps and explicit replay mode; simulated cursor movement, activity text or streamed prose cannot certify live network execution. Display blocked actions and exact reasons prominently, with ownership for resumption, rather than burying them in a success total. Project credential-safe summaries and reviewable evidence, with originals under the appropriate access boundary.

## Measured acceptance and rejection conditions

These are proposed acceptance experiments for later admission, not tests executed by this audit. Freeze scope, candidate versions, observation contract and conclusion before running them. The user has authorized Cass's separate public mapping, not provider/scanner/browser execution by this audit.

| Claim being tested | Observable acceptance evidence | Failure that rejects or narrows the claim |
| --- | --- | --- |
| The investigator acts from unfamiliar observations | URL-only start, recorded first observation, decisions referencing material actually observed, and a second action that changes when a relevant observation changes | Replays fixed signup/order paths, receives hidden source/answers, or uses unexplained IDs/endpoints |
| Relevant research affects decisions | Sampled material decisions resolve to exact study passages/corrections and explain applied limitations; compare a predefined retrieval-assisted arm later | Citations are decorative/post-hoc, stale hazards are treated as commands, or missing retrieval is called comprehensive intelligence |
| No quiet authority expansion | Controlled out-of-scope/blocked proposals are denied with zero corresponding sends/effects; denial persists across handoff/restart | Alternate tool/session/encoding reissues the same security-blocked operation, or page instructions change policy |
| Observation supports the reasoning | Reviewer can reconstruct cited visible state/content within redaction/completeness limits and distinguish browser/network evidence | Only a digest/status remains for the decisive hyperlink/text, truncation is hidden, or sanitized omission becomes absence |
| Tool execution is real | Native executor events and collected artifacts bind action, identity/context and destination; provider proposals remain separate | Live UI animates while only a replay/JSON proposal happened; planner completion masquerades as action completion |
| A finding reaches level 3 | Stated rule, identity/object/state, actual prohibited effect, legitimate/negative control, retained evidence, consequence limits, repair guidance and repeatable verification | Confidence, model votes, status codes, canary quotation or simulation verdict substitutes for effect; no permission for decisive step |
| Recovery is honest | Injected interruption leaves a retained unresolved action; resume reconciles effects before repeating; observed owned-resource closure | “Cancelled” assumed quiescent, replayed writes, stale build/session reuse or silent lost tail |
| Progress/stopping has meaning | Distinct supported observations/resolved uncertainties and explicit unsupported branches under resource limits | New wording/IDs earn novelty, all unknowns become zero/clean, goals force endless retries or require a vulnerability |
| A candidate strategy improves capability | Repeated matched scope/access/budget trials, competent manual baseline, all failures/cost/review time, fresh held-out target families when making generalization claims | Faster known-script replay, one familiar target, unequal hints/access, omitted failures or holdout tuning advertised as superiority |

For the first real agency site, report descriptive workflow/observation success and limits. Without a complete independent vulnerability inventory, recall is unknown. A no-finding report can satisfy the bounded investigation objective. “Autonomous” requires a declared interval of decisions/actions without human writing each next action; log human interventions instead of retroactively removing them from the story.

The research does not settle optimal planner/model, model diversity, parallel worker count, stopping threshold, deployment sandbox, per-target accuracy or economic viability. A later head-to-head may show existing sessions are enough, ARTEX saves coordination, CE contributes a narrowly useful analyzer, or a simpler deterministic method wins a specific question.
