Assessment
Worth a bounded evaluation as a security scanning and assessment-management base. It combines package inventory and vulnerability matching, source/configuration checks, findings, evidence and reporting. It is a larger operational platform than a simple autonomous pentesting agent. The repository also contains offensive workflows, cloud posture and runtime agents; their presence does not establish their effectiveness.

Source observations
- internal/infrastructure/tools/sast/analyzer.go and patterns.go implement deterministic line/pattern checks. The scanner has a 500 finding cap, 50 findings per file, skips files over 1 MiB and long/minified lines, and excludes dependency/build trees. These limits matter when interpreting a clean or truncated report. Separate reachability analyzers exist; the basic SAST engine is not a complete semantic audit.
- internal/infrastructure/tools/osv/scanner.go batches package identifiers to OSV and fetches advisory details. Online dependency checks disclose package/version identifiers to advisory services. CLI --offline disables live advisory and resolver/AI paths, but meaningful offline CVE detection needs populated local data.
- AI triage is optional. The documented proposer/verifier and evidence controls are promising design choices, not independently validated guarantees.
- docs/guide/installation.md distinguishes Windows development support from Linux-only sandbox/recon/egress and eBPF features.
- deploy/docker-compose.full.yml is explicitly sandbox-off development. It publishes database, object-store and API ports, includes a fallback development API token, and uses some floating image tags. It requires local hardening before any exposed deployment.
