## Shared interfaces and ownership

Implementation lives in `src/lab/`, without replacing either existing runtime. Node built-ins only for the new operational path. No provider, scanner, dependency install, privileged service, host-account change or production access. HTTP listeners bind explicitly to `127.0.0.1` and ephemeral ports. Services are closed in finally blocks and report observed cleanup. Only synthetic disposable data is used.

- Thistle owns `src/lab/target.mjs`, `src/lab/mail.mjs`, `test/lab-target.test.mjs`. `startLabTarget({mode:'secure'|'ownership-gap',port:0,mailPort:0})` returns `{origin,inboxOrigin,mailboxToken,buildId,mode,close,inspect}`. `close()` waits for owned listeners/connections to stop; `inspect()` returns trusted operator state (not exposed to investigation). Each startup is a clean generation. Build ID must bind source/config; include per-start generation separately. Actual local SMTP delivery to a dedicated authenticated HTTP-readable mailbox; no external provider claim. Target root HTML links signup/login/app and describes ordinary order use. Signup POST `/api/register` JSON `{email,password}` sends mail; login POST `/api/login` JSON `{email,password}` returns `{token,user:{id,email}}` only after verification. Mail GET `/messages?recipient=<email>` with bearer mailboxToken returns `{messages:[{id,to,subject,text}]}`. Verification is a target GET URL carried by delivered message text. GET `/api/me` authenticated returns `{user:{id,email}}`. POST `/api/orders` JSON `{description}` returns `{order:{id,ownerId,description}}`. GET `/api/orders` returns own orders. GET `/api/orders/:id` returns `{order}`; ownership-gap deliberately omits owner check for authenticated read only, secure denies foreign read. No planted admin ladder. Mail accepts only run-local reserved `.test` recipients; no external send. Target public errors contain no tokens/source/internal inspection data. Protocol/docs can be discoverable via linked HTML; no preprovided credentials.
- Ginger owns `src/lab/transport.mjs`, `test/lab-transport.test.mjs`. `createLabTransport({origins,maxRequests:100,timeoutMs:3000,maxResponseBytes:262144,deadlineMs:60000})` returns `{request,stop,stats}`. `request({url,method:'GET',headers:{},body:undefined,identity:'anonymous'})` returns a JSON receipt `{id,startedAt,identity,request:{method,url,headers,body},response:{status,headers,body,bodySha256},complete,error?}`. Body is UTF-8 response text, JSON parse belongs to caller. Evidence excludes Authorization/Cookie/Set-Cookie and credential/token bodies; retain safe body via explicit redaction and digest raw bytes without exporting secrets. Identity is operator-declared unless corroborated by `/api/me`. Only literal numeric 127.0.0.1 exact origins, no redirects/retries/proxy/DNS arbitrary targets; reject URL credentials, malformed/extra origins and shutdown/budget violations before send. Stop destroys in-flight requests, prevents new ones and waits for quiescence. Stats include attempted/sent/completed/errors/denied/active/stopped, not just one success count. No arbitrary shell/helpers/browser in this first restricted executor.

## Acceptance and implementation order

Eight stages are URL+scope; self-registration; delivered-mail verification; legitimate use; observation-led hypothesis and disconfirmation; actual test/control receipts; independent challenge/replay; canonical report plus verified stop/reset. We will perform secure and explicit guided vulnerable-control runs and retain failures, unknowns, raw digests, redaction limits, total request counts and assistance. Any claimed security effect needs actual corroboration, not a status or narrative. Existing verifiedFindings remains empty unless its independent authority contract is truly met; guided reproduced effects can be reported with limitations in owner-action category. Real changed-build repair is not fabricated.

Runtime enforcement covers only the new typed loopback transport, not unrestricted host coding sessions. No arbitrary generated code execution is admitted. A broader agent sandbox and external inbox remain separate readiness gates. If any boundary cannot be enforced, report its limitation and do not widen access to make a test pass.
