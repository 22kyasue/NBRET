No Django app, database, import, ticket, notification or production service was run or changed.

A reporting/collaboration system organizes evidence and lifecycle. Its input may be scanner reports, manually adjudicated findings, assets and identity/context; its output includes normalized findings, deduplicated groups, statuses, histories and external issue integrations. Parser success, deduplication and closed status establish different things from a validated security flaw or a verified fix. The operator is usually an assessment/app-security analyst; prerequisites include reliable asset/test/environment identity, schema/parser version and clear lifecycle policy. Main failures are lost provenance, mistaken identity merges, partial scans treated as negatives and stale/changed matching keys. Integrate using original artifacts plus explicit transformation receipts, not a finding title alone.

## Nmap parser, full file

`dojo/tools/nmap/parser.py` 1–240 complete:

* 1–34 uses CPE and defusedxml parsing, checks root tag by substring and takes scan start time with datetime.fromtimestamp. It suppresses ValueError only there; missing attributes and malformed structure have other failure paths. The timestamp is naive/local-converted at this point, not a retained timezone-aware capture observation.
* 36–64 assumes an IPv4 address element and iterable hostnames, builds descriptive host/PTR/OS text. A hostname may become the location host in preference to IP. PTR and OS accuracy remain upstream assertions; this transformation does not authenticate them.
* 65–112 creates URL/Endpoint locations according to the location feature flag and imports **only state=open**. Copies selected product/version/extrainfo and the first script output. It does not retain state reason, reason TTL/IP, service identification method/confidence or every script in these fields. Closed/filtered/open|filtered omission is a parser projection, not absence from the original report.
* 114–148 specially handles vulners script entries and otherwise creates Info open-port findings. Its open-port dedupe key is **nmap:port**, without protocol/host; findings at the same numeric port can share one title/severity while descriptions/locations aggregate. Thus finding count is not host-port-protocol count. This is source-established grouping behavior, not a demonstrated deployed reporting incident. Preserve per-location protocol and raw XML.
* 150–168 maps numeric CVSS into severity labels. 170–240 parses CPE/vulnerability tables, transfers tool IDs/components/severity, adds CVE IDs only under the expected type and aggregates by vulnerability tool ID with occurrence count. Advisory/CPE matches remain scanner/script evidence, not an executed vulnerability validation. Missing/malformed values and parser resource limits require separate tests.
