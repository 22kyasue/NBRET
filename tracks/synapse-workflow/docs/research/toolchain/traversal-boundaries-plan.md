# Predeclared synthetic traversal boundary tests

2026-10-17, before execution. Use the same pinned dawgs v0.9.2 resolved by BloodHound and portable Go1.27.2, offline acquisition/read-only module/isolated caches. Test our own Go file directly from the BloodHound module context. Database and transaction interfaces are embedded only to satisfy types; the mock overrides ReadTransaction and GraphQueryMemoryLimit, and the fixture driver never performs a graph query. One worker; at most three synthetic nodes; no network/database.

Four predefined oracles: (1) a three-node finite chain visits exactly 1,2,3 and returns nil; (2) a sentinel driver error is returned with errors.Is; (3) the driver records root, cancels parent context and returns context.Canceled, leaving only one visit and nil aggregate error at the reviewed filtering branch; (4) a one-byte graph query memory budget rejects before invoking the driver and returns ops.ErrGraphQueryMemoryLimit. Each context has a two-second outer deadline; Go test has 15 seconds and runner 60 seconds. A mismatch is a failed hypothesis, not to be redefined after the run. Preserve failure/success output unchanged; receipt refuses overwrite. No actual timeout load, unbounded queue or large graph is used.

Result scope: mock engine boundaries only. Cancellation nil does not itself prove callers mishandle partial results; they may inspect context and status. Memory-budget assertion does not establish total process accounting or correctness of production drivers. No integration tests, dependency downloads, credentials, production changes or cleanup beyond child exit.
