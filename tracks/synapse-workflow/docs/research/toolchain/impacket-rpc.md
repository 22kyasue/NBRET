# Protocol client study: Impacket RPC endpoint observation

Fortra Impacket **0.13.1**, release tag `impacket_0_13_1`, commit `c456746d7a0f0bb25e8968a59f25aae1ad519935`. Clone matched the previously retained catalog resolution; 340 implementation/configuration/test/license files inventoried. This adds source review to earlier metadata. No installation, credentials, RPC connection, endpoint query or remote test ran. Impacket is a Python protocol library with example clients, not an OS distribution, VPN or complete identity graph collector.

An authorized operator can use protocol clients to examine a protocol-specific claim after broad discovery. The selected client returns endpoint-mapper registrations grouped by interface UUID, with binding strings, annotations and static known-provider labels. These are **advertised registrations plus interpretation**, not proof of reachability, successful authorization to the advertised service, actual executable inventory, vulnerable version or exploitation. The RPC endpoint mapper and a generic HTTP/SOCKS proxy are different protocol roles; RPC-over-HTTP transport is not a general VPN.

## Entry, transport and output

`examples/rpcdump.py` 1–211 complete:

* 1–37 license/import boundary; public source under the modified Apache terms described in the catalog, not blanket Apache-2.0 equivalence.
* 38–94 selects an RPC transport binding by supported connection mode, stores credential material and sets it for SMB or the RPC HTTP proxy. Proxy authentication is explicitly separate from MSRPC-level authentication. A comment saying authentication is not needed for a mode is the example's behavior/assumption, not a finding about every target's policy.
* 95–110 catches fetch exceptions, logs protocol failure and gives selected proxy errors explanatory handling. Other failures can continue with the initially empty entries list. 112–151 groups UUIDs, builds bindings, adds static known-protocol/provider labels, decodes annotations and prints counts or “No endpoints found.” Preserve logs/error state: an empty-looking summary after protocol failure is not a negative enumeration finding. Formatting/decode failures can occur after fetch as well.
* 154–166 connects, calls the lookup helper and disconnects on normal return. No finally around this sequence: bind/request/parser exceptions require a separate cleanup oracle before claiming reliable release.
* 168–211 configures CLI, parses supplied identity/target, prompts when appropriate and invokes the client. Host display name and optional network destination can differ in selected transports. CLI-embedded secrets can enter process/history/capture records; use synthetic identities in labs and keep real credentials outside shared evidence. No credentials were obtained or used here.

`impacket/dcerpc/v5/transport.py` 1–606 complete:

* 36–110 parses/composes UUID/protocol/address/endpoint/options; uses regex.match rather than fullmatch and assumes a match. A parsing helper is not scope validation or canonical destination enforcement. 113–150 dispatches UDP/TCP/HTTP/SMB/local transport, rejecting unknown sequence.
* 152–296 stores name versus host, port, timeouts, fragmentation and multiple credential representations. Strict hostname validation defaults off and is documented here as SMB-specific. Credential getters return sensitive values; no independent secret store/sandbox is implemented in this object.
* 298–340 uses OS resolution/datagram sockets with a 30-second configured timeout and 8192-byte receive. 341–395 uses stream resolution/connect/close, socket send and optional send-fragment loop, exact-count receive or an 8192-byte read. Send return counts are not accounted for by these send branches; possible partial-write behavior needs an owned fake-socket test, not an assumed real data-loss finding. Per-socket timeouts are not a whole operation or engagement budget.
* 397–474 delegates direct legacy RPC-over-HTTP or RPCProxyClient based on binding options, separates proxy URL/credentials, checks a direct greeting and delegates send/receive/close. RPC proxy TLS/certificate/HTTP authentication internals are unread dependencies; https syntax alone is not evidence of verified identity.
* 476–578 supports owned versus externally supplied SMB sessions, optional Kerberos, hostname-validation configuration, IPC tree/pipe access and transport reads/writes. Disconnect logs off/closes only owned sessions; reusing another caller's session changes credential/lifetime ownership. SMB signing/encryption and authentication implementation must be read in SMBConnection/SMB classes before making channel-security claims.
* 580–606 opens a local Windows pipe through OS file APIs, explicitly not LPC; closes handle and performs direct reads/writes. A local transport capability is not permission to access arbitrary PC pipes, and none was exercised.

## Endpoint representation and continuation

`impacket/dcerpc/v5/epm.py` 968–1389 partial. 968–1068 defines counted protocol “floors” for UUID/version, representation, port, pipe, hostname/address. 1070–1083 parses a tower's declared number of floors using a fixed class list; Structure/NDR length/bounds behavior remains unread, so no malformed-tower safety claim follows. 1093–1200 defines lookup context handles and NDR call/response layouts. 1207–1253 binds the mapper, accumulates up to 500 requested entries per call, parses towers and continues until null context handle. This is pagination, not a total-entry/time/memory bound; no repeated-handle guard appears in this helper. Normal cleanup depends on whether it created or received the DCE object; exceptions are not enclosed in finally here. 1255–1349 constructs mapping requests and extracts one advertised binding; 1351–1389 formats protocol-specific floor strings. Neither helper proves advertised destinations are approved or reachable. Static UUID/provider tables in 1–967 remain unread; table-derived names are not observed binaries.

`impacket/examples/utils.py` 1–345 complete. 20–62 parses identity/target strings and handles @ in passwords. 72–89 can make SMB discovery/login attempts to determine a machine name; a utility function is not necessarily offline. 91–211 builds a Kerberos LDAP bind using optional cached/supplied tickets or KDC acquisition. This expands identity and network prerequisites beyond the selected RPC client and was not invoked. 213–247 selects LDAP/LDAPS and authentication; 253–294 contains a separate LDAP login helper that retries LDAPS for stronger-auth requirements. Dependencies determine certificate/channel validation. 298–319 parses identities/prompting; 323–345 handles IPv6 scopes and opens sockets. Reading all helpers does not establish they all run on the chosen RPC path.

`setup.py` 1–86 complete. Declares version0.13.1, packages/example scripts and broad dependency constraints for ASN.1, cryptography, TLS, LDAP and other utilities. Includes git subprocesses during setup metadata evaluation. This file was **read, not executed**; no installation was required for source review. A release source pin with unconstrained transitive resolution is not a reproducible runtime environment.

`tests/dcerpc/test_epm.py` 1–127 complete. Real connect/request tests across SMB/TCP and NDR/NDR64, explicitly marked remote. They were **not run**. A test filename does not imply an isolated fixture. Missing synthetic coverage remains meaningful: protocol failure versus empty results, malformed tower/annotation, repeated paging handle, partial TCP writes and cleanup on request error need controlled mocks before runtime conclusions.

Cross-tool handoff: Nmap service observation → approved protocol-specific endpoint query → raw registration and transport/identity/error evidence → identity analyst's hypothesis → separately authorized seeded capability check/retest. Do not turn an endpoint listing into a graph permission edge or exploit finding without its own oracle. Dangerous administrative/credential/relay examples in the broader package remain unreviewed and unexecuted, with no authorization implied by downloading their source.
# Continuation: complete endpoint mapper module

`impacket/dcerpc/v5/epm.py` at the existing 0.13.1 pin is now read completely, 1–1389. Initial 968–1389 parser/helper review is preserved; newly closed 1–967 includes imports/error representation, static UUID/protocol annotation dictionaries, constants and tower format commentary. The dictionaries attach human labels to advertised identifiers; they neither authenticate the serving process nor show that an operation is authorized/reachable. `KNOWN_PROTOCOLS` contains repeated UUID keys (for example LSAD/LSAT and generic COM/removable-storage entries), so ordinary Python dictionary overwrite semantics collapse alternate labels. A displayed name is a lookup choice, not a complete protocol inventory or live module identification.

Tower commentary specifies a little-endian floor count, length-prefixed left/right sides and an opaque payload inside ordinary NDR structures. Parser correctness therefore depends on both outer NDR bounds and inner Structure length handling. Those dependency implementations/tests remain queued; this full module read does not credit them or establish malformed-input resilience. SessionError construction reads packet status, while formatter fallback describes unknown codes. Avoid using a label/status presentation as evidence of capability. No remote EPM call or new runtime test was performed.
