## Inputs, provenance and routes

The resolver constructor allocates an implementation and initializes static hosts-file tables; construction itself would read local configuration. Hosts forward keys are exact string/type pairs, while wire response-name matching uses case-insensitive comparison. PTR cache keys are addresses; cached names have no TTL field. Hosts entries and later PTR responses share that cache. A cached result establishes a stored association, not a fresh DNS observation, service identity, ownership or assessment authorization.

Server setup 597–630 adds rather than replaces entries. A hostname supplied as a DNS server is passed through resolve_all at1406–1414, so even the comment saying server setup does no connecting does not establish absence of resolution traffic in its dependency. Actual Windows discovery1441–1498 uses GetAdaptersAddresses, enabled/up adapters and optionally a mapped interface GUID; the introductory registry description is stale for this body. Unix reads resolv.conf. Hosts-file tables initialize once per process; cache initialization adds hosts entries without clearing existing PTR cache.

Async resolve729–805 creates an Nsock pool, passes device/proxy settings, and connects every server using **UDP port53** at1418–1433. Nsock's reviewed proxy redirection predicate is TCP-only. Merely passing proxy_chain therefore does not establish proxy carriage for these DNS requests. Requested device binding can fail without aborting socket creation. System resolution uses getnameinfo/resolve_all, whose OS policy is separate from the custom server list and proxy setting. Truncation, unprocessed CNAME and some nonstandard/single-label negative responses can defer to the system resolver at1275–1344. A custom DNS list is thus not proven exclusive resolution egress. No traffic was generated to validate deployment-specific routes/DNS behavior.

## Scheduling, completion and cleanup

add_request656–727 first consults hosts/cache, then allocates request state and random-unique-u16 IDs. Internal ANY means separate A and AAAA requests, not a wire ANY query. Per-server capacity is clamped10–100, with retry time arrays based on server count and at most three servers tried. Writes use a512-byte request buffer and100ms write timeout. records retains timed-out IDs so late responses can still match; request status READY/NORESULT/DONE prevents repeating selected completions. These are resolver load heuristics, not an authorized-scope filter or a total engagement deadline.

The initial nsock_loop return is stored at754, but subsequent loop calls770 do not update status. Consequently its while condition keeps the initial TIMEOUT value; later ERROR/QUIT/NOEVENTS handling must be traced against total_reqs and queue state before claiming prompt termination on every engine failure. Write errors move requests back to the server queue without visibly decrementing reqs_on_wire at947–961; repeated-error accounting requires follow-up. close_dns_servers silently cancels descriptors and drains queues under non-READY assertions, clears record maps and requests loop quit, then the pool is deleted. Deferred system requests run after transport cleanup. No shutdown/error branch was runtime-tested.

reset418–434 tests deferred_reqs nonempty but accesses/pops new_reqs in its second loop. This is a concrete source container mismatch, with reachability depending on interrupted/reinitialized deferred work. The public Resolver header has no destructor declaration while its constructor allocates impl; ownership/copy/lifetime callers need review. These are unresolved source questions rather than demonstrated incidents.

system_resolve1634–1678 returns true after a PTR getnameinfo failure because that branch has no failure return. Its caller can increment ok without a newly assigned name. Forward failure returns false. Statistics therefore require operation-specific interpretation; ok does not universally establish a fresh mapping. Summary statDone includes SERVFAIL counts even though its handler may trigger retries; completion percentage is bookkeeping, not proof every requested name has a trustworthy answer.

## Response validation and parser boundaries

handle_read1202–1361 parses event-owned bytes before callback return, requires a response, nonempty query, selected flag/error checks, a per-server outstanding ID, non-DONE state, query class/type and case-insensitive requested-name match. Answers must have IN class and matching owner/type; ordered CNAME changes the name considered for following records. This is meaningful matching, contrary to saying it accepts every DNS packet. The transport uses connected UDP; OS/native source filtering and random-ID guarantees remain dependencies. No DNSSEC validation or independent authority proof is implemented in this reviewed path.

The opcode check uses DNS_HAS_FLAG(f, OP_STANDARD_QUERY), where the enum value is zero: the macro `(v & flag) == flag` is true for any opcode. Likewise ERR_ALL is0x0007 rather than the full low-four-bit RCODE mask. The later query/ID/name checks remain contrary evidence to a blanket arbitrary-response claim. A runtime/protocol oracle was not run; practical impact is open.

Factory serialization1838–1912 checks available room, label63/name255 limits and writes a single IN query. Build failure returns zero; put_dns_packet_on_wire does not visibly reject zero plen before enqueueing the write. parseDomainName1964–2030 restricts labels, total decoded name and backward compression pointers, and rejects missing termination. It has no explicit pointer-hop/visited set; backward-only is a local pointer rule rather than proof every possible label/pointer graph terminates. No malformed native input was exercised.

Answer parsing2071–2112 verifies the declared RDATA extent fits the packet, but calls its typed record parser with the whole packet maxlen and does not require consumed length equals RDLENGTH. A/AAAA consume4/16; PTR/CNAME decode names with packet-level pointers. Packet parsing2125–2156 parses question and answer counts but only reads, then ignores, authority/additional counts; consumed bytes need not equal full packet size. Unsupported answer types return failure. Claims of whole-message canonical validation would exceed this implementation. Copy constructor/assignment clone record pointers without a null check, and assignment does not free an old pointer; normal parse/list-copy usage and other callers need tracing before asserting reachable faults/leaks.

PTR conversion1737–1836 includes the short-suffix guards covered by tests. It still uses a three-entry decimal place_value array without an explicit per-label digit limit, and does not enforce four complete IPv4 components or32 IPv6 nibbles before setting family. The reviewed async response path does not call ptrToIp directly; all repository callers are an explicit follow-up, not an assumed remote exploit chain.

## Cache bounds and unresolved questions

Caller reconciliation, using the already fully credited nmap_dns.cc:95–187 (no new line credit): the ordinary Nmap wrapper owns one static Resolver and initializes AF/source/options/proxy/servers only on its first call. This narrows the earlier per-instance ownership question: repeated ordinary calls do not allocate a new Resolver each time, while cache/configuration state can persist across batches. Init resets request/stat bookkeeping but the reviewed host-cache initializer does not clear prior PTR associations. Dynamic option changes after first setup are not automatically reflected by this wrapper; actual option mutability and embeddings require caller evidence.

The wrapper explicitly falls back to system resolution when no mass-DNS server is available at133–139, in addition to the response-driven fallback inside massdns. It calls Resolve without receiving a success/failure result and ends the progress task afterward. That is a source completion sequence, not a verified mapping count. Crucially, reverse-DNS propagation174–178 sets a Target hostname only when the resulting string is nonempty. This is contrary evidence against claiming the system PTR helper's true-on-failure automatically invents a target hostname: its status/statistics can be misleading while this caller still withholds an empty name. The caller skips non-UP targets unless always_resolve is set, preserving the earlier distinction between resolution policy and live-host proof.

`nbase/nbase_misc.c:1–861` is fully read. sockaddr_storage_equal delegates to comparison of address family and address bytes only: it excludes port and IPv6 scope ID. Thus the PTR cache has an address-family namespace (contrary to saying IPv4/IPv6 are simply mixed), but no explicit interface/scope or resolver namespace in this equality. A scoped-link-local collision depends on actual inputs and reuse, not demonstrated here. Unsupported equal families reach assert then return zero if assertions are removed; normal callers supply IP addresses.

The socket-bind helper returns success when SO_BINDTODEVICE is unavailable at compile time; where supported it reports setsockopt failure, which Nsock already deliberately ignores. Nonblocking helpers preserve Unix flags and return errors, but Windows ignores ioctlsocket's return and reports zero; Nsock creation does not check its return. These source paths reinforce why requested settings alone are not verified isolation. Windows duplicate handles are noninheritable, while newly created WSASocket uses its default inheritable behavior; process creation/handle inheritance policy is a separate caller boundary. None was invoked.

The full utility file also contains platform error/static-address formatting, fselect stdin bridging, checksums, time conversion, hexdump and file/executable discovery. Windows fselect's no-descriptor branch dereferences tv to sleep; public callers allowing NULL need checking before a fault claim. Unix delegates select directly. CRC32/CRC32C/Adler32 detect selected transmission changes and are not cryptographic authenticity evidence. hexdump has an explicit allocation-overflow bound and returns caller-owned memory; its printed offsets wrap16bits. Readability/path helpers are observations at a moment, not durable permission or trusted-code attestation. No files or checksums were exercised through these upstream helpers.

Dependency continuation: `nbase/nbase_rnd.c:1–409` is fully read. get_random_unique_u16 uses process-static seeded16-bit LCG state followed by odd-multiplier affine, rotation and XOR permutations. The intended no-repeat span is finite16-bit state, not a cryptographic authentication property or global uniqueness. Seed bytes come from the shared ARC4-style generator; Windows CryptAcquireContext/CryptGenRandom return values are not checked here, and Unix seed reads retry EINTR but do not require a full successful read. The file itself describes casual-use randomness and weak fallback entropy. This is not a demonstrated prediction attack; no generator was invoked or seed observed. OS provider/native implementation and caller concurrency remain open.

A whole-tree text search for ptrToIp call syntax found only its declaration/definition and the three test sites in this checkout (excluding CHANGELOG/XML/HTML). This is contrary reachability evidence: the reviewed malformed-label questions are not established as reachable through the resolver's received-response path. It is not proof against indirect/dynamic or downstream consumers. Do not convert an exposed helper's unchecked shape into a claimed remote scanner vulnerability.
