## Synthetic engagement evidence graph

**TC13 — relationship builder identity/position mismatch.** The pinned dawgs PostgreSQL relationship-create builder aliases unseparated endpoint/kind keys and uses stored relationship IDs as property-slice indexes. Four predefined in-memory observations executed its unchanged Add method using real pinned graph types and inert row/mapper stand-ins: endpoint-key alias, duplicate second zero-ID relationship modifying the first bag, recovered ID99 duplicate index panic, and correct first-zero-ID control. [Plan](pg-builder-plan.md), [receipt](pg-builder-receipt.json), [caller and limitation analysis](identity-analysis.md). Migration batch callers are source-traced; SQL persistence and full-application consequences are unvalidated. Normal graphify UpdateRelationshipBy is a separate path. Suggested regressions preserve typed identity, explicit indexes and row/property association across order/batch permutations.

**TC12 — cancelled traversal can return nil without complete work.** At actual dawgs v0.9.2, BreadthFirst excludes context.Canceled/graph timeout worker errors from its aggregate. The predefined mock fixture cancelled after visiting root and returned context.Canceled; the v2 receipt establishes one visit, cancelled context and nil aggregate, while a sentinel error and finite-chain controls behaved as expected. [Trace, original build failure and successful receipt](identity-analysis.md). This is a lab-validated helper boundary, **not** a demonstrated application false-negative: callers may inspect context/status, and no real DB/API/query ran. A report wrapper must preserve completeness/cancellation independently from a nil helper error.

The practical unit is **a claim and its oracle**, not the name of the tool that emitted it:

Scope revision + test identity + vantage + versions → observation → interpretation → controlled comparison → reviewed finding → remediation build → retest with the same intended property.

Each arrow can lose information. A proxy response may be synthetic; a scanner service label may be table-derived; an identity edge may be newly ingested old data; a warning may accompany a successful helper return; a report may omit raw errors. Preserve the original artifact and the transformation chain rather than treating a report title as the source of truth.

For a fictional invoice test, the oracle is cross-tenant seeded content under a known identity, with legitimate controls. For fictional identity membership, it is the specific collected relationship plus current permitted capability and edge-specific preconditions. For defender validation, it is execution → collected telemetry → alert → human/system response, not a tool's process return. See [synthetic narratives](map.md) and complementary [assessment-evidence work](../assessment-evidence/).

## Opportunities are hypotheses

An evidence-preserving adapter could retain raw method/reason/time/identity/transformation/error fields across scanners and reports. It is valuable only if it reduces adjudication time or prevents mistaken claims; measure that against a baseline using seeded ambiguous cases. Do not infer customer demand from these code findings.

A capability-specific execution envelope could enforce destination, operation, identity, byte, connection and time budgets outside extensions. Test whether it fails predictably when a handler crashes, streams early or changes destination, without breaking legitimate fixtures. A regex allowlist or a display filter is not an equivalent experiment.

A temporal identity-evidence model could distinguish observed-at, ingested-at, valid-until, denied-source and inferred-edge states. Measure whether it reduces stale-path claims and makes remediation/recollection decisions clearer. This is a proposed engineering experiment; no business strategy or willingness-to-pay claim has been established.
