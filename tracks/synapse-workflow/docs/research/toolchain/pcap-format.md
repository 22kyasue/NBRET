# Classic pcap: concrete parser and writer

Wireshark v4.6.9 pin `2d548b197c7582332f143c15259e1650aff7cc26`, `wiretap/libpcap.c` **1–1988 complete**. Raw URL/hash/retrieval retained in snapshots.json; added without resetting earlier reading. This is Wiretap's own file-format implementation, **not** semantic review of the separate libpcap capture library. No binary or malformed-capture test ran.

* 1–186: GPL-2.0-or-later header, per-file endianness/version/variant/FCS state, callback declarations and supported historical variants. Link-layer type and FCS fields are distinct metadata.
* 188–350: reads magic and global header, identifies native/swapped/nanosecond/Ixia/modified variants, skips known extras, swaps required fields and rejects unsupported old major versions. Recognized magic is format recognition, not integrity or trustworthy origin.
* 352–518: installs read/seek/close callbacks, records snaplen, handles historical swapped captured/original lengths and AIX heuristics, checks reserved link-type bits, maps encapsulation, extracts FCS length. Compatibility inference can change interpretation; preserve format/version and original bytes.
* 520–722: chooses heuristic versus known variant, treating pipes differently because lookahead/rewind is constrained. Standard magic on a pipe defaults to standard pcap; ambiguous modified format on a pipe is rejected. Sets timestamp precision and special Nokia encapsulation; normally generates **one interface-description block because original interface count is unknown**. A generated interface is not provenance that all packets came from one actual interface.
* 724–828: variant inference tries at most three records per candidate, rewinds, selects the first zero-problem candidate or least-bad score. This is heuristic compatibility, not a complete-file validation pass.
* 830–1016: scores short header reads, fraction-of-second range, captured-length maxima/snaplen, large original lengths and captured-versus-original mismatch. Snaplen inconsistency increases a heuristic score; it is not invariably fatal. These numeric thresholds answer different questions and are not a global memory budget.
* 1018–1283: reads/scores historical variant fields (interface/protocol/type/Nokia), skips payload under the chosen bounded length, distinguishes hard errors from short-read scoring. Comments and empirical constants are maintainer reasoning, not independently verified historical facts here.
* 1285–1413: sequential read records its offset; seek read uses the independent random handle and treats missing requested record as short read. Concrete packet reading rejects captured lengths beyond encapsulation maximum, handles AIX padding with checked subtraction, delegates pseudo-header processing, records captured/original lengths, normalizes timestamp units, reads payload and delegates post-processing. Header snaplen is not itself the only accepted-packet length bound. Pseudo-header/encapsulation helpers remain dependency boundaries.
* 1415–1486: reads the selected per-record header size, swaps byte order and optionally swaps historical length fields. A parsed original-length value is a capture record's assertion, not bytes actually present in the file or proof observed on the wire.
* 1488–1602: writer rejects per-packet encapsulation and unmappable types, writes format 2.4 header, substitutes an encapsulation maximum when snapshot length is unknown (zero), and selects microsecond/nanosecond/modified callbacks. Output defaults are transformations, not original measurement evidence.
* 1604–1682: releases encapsulation-private state; writer accepts packet records only, checks file/packet encapsulation equality and length maximum using a widened sum, writes header/pseudo-header/captured bytes and propagates errors. Partial output can exist when a later write fails; atomic artifact publication is a wrapper concern.
* 1684–1878: timestamped packet writers reject negative/greater-than-INT32_MAX seconds; microsecond output divides nanoseconds by 1000. Modified formats fill selected legacy fields with zero; Nokia preserves its extra bytes. A round trip or conversion can lose precision and metadata, even when packet payload survives.
* 1880–1974: format capabilities declare packet blocks **without comments or other options**; registers pcap variants, compatibility names and Lua names. Converting a richer capture/evidence container to classic pcap cannot be assumed to preserve annotations, decryption blocks, names or every interface identity. 1976–1988 editor metadata only.

Connect this to [Wiretap/epan/filter wrappers](packet-dependencies.md): successful opening may involve heuristics and synthesized metadata before record dissection begins. Evidence preservation requires the immutable original plus explicit export transformation, errors, precision and metadata-loss notes. No authenticity, full parser security, real capture accuracy or exhaustive format fidelity has been established. Pcapng is a separate unread format parser; newly inventoried packet-dispatch/filter-VM files also remain unread until annotated.
