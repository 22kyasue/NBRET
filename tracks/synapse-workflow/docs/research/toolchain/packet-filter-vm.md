## VM contiguous annotations

* 1–77 maps opcodes, including separate ANY/ALL comparisons, field/reference reads, existence tests, regex, arithmetic, sets, function calls and branches. Display filtering is not just substring matching or packet-capture BPF.
* 79–245 manages instruction/value allocation, reference counts, owned constants/regex/ranges and register/field/function references. 247–742 renders typed values, instructions, stack arguments and references for diagnostics, freeing temporary strings. A diagnostic VM dump is executable-plan provenance, not evidence any packet matched.
* 744–827 sorts protocol layers, supports layer ranges/negative offsets and obtains raw bytes or display-label strings. Raw-field retrieval clips field length to available captured bytes and returns NULL for invalid remaining offset. A raw field need not equal the entire original wire payload; displayed labels are another representation.
* 830–962 loads decoded field occurrences, filters by protocol-layer range, handles same-name field chains and caches values in registers for the current run. Owned raw/label values differ from borrowed decoded values. Missing field arrays return false/empty; semantic meaning depends on the compiled branch plan, not an isolated helper's boolean.
* 964–1038 loads stored references with layer selection and cached registers. These are configured comparison inputs, not fresh packet observations. Preserve them with the filter if used.
* 1040–1161 compares **cross-products of occurrence arrays** using any/all semantics; empty loops have helper-level all/any defaults. Regex matching delegates to fvalue_matches and its compiled regex. Do not extrapolate full display-filter behavior for absent fields from vacuous helper results: code generation includes read/existence/branch control and remains a dependency. No exact filter truth table was tested here.
* 1163–1258 evaluates set membership/ranges per occurrence; assertions expect successful reads before membership testing. 1260–1316 clears registers and creates slice/length values; slicing assumes semantic checks have already rejected unsupported types.
* 1318–1470 invokes registered display-filter functions and typed arithmetic. Binary operations iterate operand cross-products; failed typed operations log at noisy level and omit the failed value. Function definitions, field types, regex limits and arithmetic internals remain unreviewed dependencies. No per-packet total operation/time budget is explicit in these helpers.
* 1472–1588 stores constants, manages function/set stacks and tests decoded-field existence across same-name registrations/ranges. These mechanisms operate on the protocol tree; they do not prove the capture contained every relevant packet or that dissection was complete.
* 1591–1828 executes compiled instructions with an accumulator, register reads, comparisons, arithmetic, stack/set operations and conditional jumps. RETURN optionally retains selected values, clears register overhead and returns the accumulator. It asserts on unexpected opcodes/fallthrough, relying on trusted compiler-generated instructions. Reading this VM does not establish safe execution of arbitrary attacker-supplied bytecode, nor is such bytecode accepted/tested here. 1830–1842 editor metadata only.

## Record-to-decoder handoff

`epan/packet.c` 540–749: 543–564 releases data-source list/marks frame dependencies; 566–588 registers late initialization routines after protocols/filters are ready. 593–746 is complete dissect_record: primes first-pass postdissector fields, initializes packet information, obtains timestamps from frame metadata, sets pseudo-header by record type, resets address/conversation/direction fields, computes relative time and selects modified versus original packet block. It constructs a tvbuff from captured bytes while clipping reported length to INT_MAX, calls the frame dissector, marks selected malformed-length exceptions and releases block state/marks frame visited. A malformed annotation is not a repaired payload; modified blocks and original bytes must remain distinguishable. Frame dissector/protocol selection, actual protocol dissectors, reassembly, tvbuff bounds and callback exceptions remain separate review boundaries.

The source-supported path now includes capture format parsing → record metadata/bytes → dissection handoff → decoded-field VM reads → any/all/regex/set decisions → TShark projection and error-preserving output. Complete VM and pcap files do not imply complete filter grammar/compiler or every protocol. An eventual owned offline oracle should seed repeated fields, missing fields, truncated records, display/capture filters, timestamp precision, malformed annotations and partial output, preserving exact decoder settings and input/output hashes.
