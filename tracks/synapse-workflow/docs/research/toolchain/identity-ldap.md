# Identity collection: LDAP transport, coverage and lifetime

This is source review of the **Stable candidate** SharpHoundCommon v4.9.1, commit `1b8c9eabe3753bac13fcd0fe9e271e02bcd4ebe7`, not proof of the Dev wildcard dependency used by SharpHound's default configuration. No LDAP server, directory account, domain join or collection ran. File hashes and read credit are in [queue.json](queue.json).

The collector orchestration and emitted JSON connect to this library through the pool manager; [identity-flow.md](identity-flow.md) traces their ingestion into the graph. A graph relationship represents collected and interpreted observations, with coverage constrained by the authenticated principal, naming context, collection flags, queried hosts, time, failures and later reconciliation. A missing edge cannot alone establish that a permission or path is absent.

## Contiguous annotations

Query-construction continuation2026-10-17: `LdapProducerQueryGenerator.cs:1–191`, `LdapQueryParameters.cs:1–48`, `LdapQuerySetupResult.cs:1–12`, `LdapQueries/CommonFilters.cs:1–29`, `CommonProperties.cs:1–123`, `LdapFilter.cs:1–339` and `test/unit/LdapProducerQueryGeneratorTest.cs:1–122` are fully read, not executed. The generator translates collection-method flags into separate default/configuration-partition filters and requested attribute unions. ACL/object/container methods broaden default object kinds; site/certificate configuration collection selects different classes and properties. Duplicate property additions are removed by Distinct, so duplicate calls alone do not imply duplicate LDAP results. In the narrow default Trusts branch the generator adds domains and ComputerMethodProps instead of DomainTrustProps; actual trust-processor queries/callers are needed before asserting lost trust coverage.

CommonProperties lists requested fields, including potentially sensitive directory attributes; requesting them does not prove they are readable, returned or safe for general report distribution. Type-resolution, base, ACL, group, certificate and site sets are different projections, not complete directory snapshots. No directory credentials/data were accessed. CommonFilters uses fixed predicates and delegates SID/GUID encoding to Helpers, an exact dependency still queued.

LdapFilter combines object-kind alternatives with OR and mandatory conditions with AND, deduplicating exact strings. Its FixFilter only adds missing leading/trailing parentheses; it does not parse/escape arbitrary LDAP filter syntax. AddFilter is a raw filter API, so this is not an injection finding without an untrusted-data caller. GetFilter returns an empty string with no parts/mandatory terms, while GetFilterList enumerates no entries with no object parts even if mandatory conditions exist; caller use determines the coverage implication. Built-in computer matching includes managed service accounts unless the explicit excluding method is chosen. Configuration partition scope and authenticated visibility still come from later setup.

LdapQueryParameters defaults to subtree search, empty requested attributes, ordinary catalog and no security descriptor/deleted objects. Absolute and relative search-base setters clear the other field. QueryID reads a static integer before a separate atomic increment; concurrent instances can share the logged ID. This is query-log correlation metadata, not object SID/GUID or evidence of graph collisions. GetQueryInfo logs filter/domain/base/ID; it does not include relative-base/naming-context in that string. SetupResult carries mutable wrapper/request/server/success/message, not enforcement by itself.

The selected generator tests cover builtin-domain/site/certificate combinations and presence/absence of selected properties. Several expected filters use the same builder as the implementation; equality does not independently validate LDAP grammar, server semantics or authorization. They do not cover every method combination, narrow Trusts properties, empty/mandatory-only filters or concurrent log IDs. Read tests are evidence of intended assertions, not a passing test receipt. Next follow actual caller consumption, Helpers encoding and ACL/property processors and their complete tests before concluding collection completeness.

`src/CommonLib/LdapConnectionPool.cs` 1–1122, fully inspected:

* 23–84: separate ordinary/global-catalog bags, domain exclusion cache, metrics and timeout helpers. The semaphore creation is commented out pending a deadlock investigation. Configured MaxConcurrentQueries therefore does not create this pool's semaphore at this pin; caller concurrency is a separate constraint. Ordinary, paged and ranged helpers disable adaptation with a two-minute maximum; connection testing uses adaptation.
* 86–260: ordinary query setup failures log and end enumeration. Successful setup checks cancellation, submits a request, retries server-down failures with replacement connections, backs off on busy/timeouts, and yields either a failure result or wrapped entries. Connections are returned before entry enumeration. Normal result counts alone omit the setup-failure distinction. Cancellation and throwing/early-disposed consumers need specific lifetime tests; ordinary source reading is not such a test.
* 262–454: paging uses a 500-entry request and server cookie. Server-down recovery deliberately reconnects to the original server because cookies are server-bound. Entries already yielded remain observations if a later page fails. Missing response/page control continues the loop; the server-down branch has an inner bounded reconnect loop but no increment/guard of the outer queryRetryCount there. Do not describe these constants as a universal total-engagement retry limit. Cookie exhaustion or empty entries ends paging.
* 456–486: setup obtains a pool connection and constructs the search. Several failures end the iterator rather than producing a uniform structured failure stream. Logs and explicit coverage records are necessary complements to the JSON dataset.
* 488–666: ranged attribute retrieval (large group membership is one consumer) asks for range=0-*, follows returned attribute names/counts, yields values incrementally, and stops on terminal * or unexpected entry counts. Busy/server-down handling and early exits differ from ordinary paging. This is not a transactional snapshot of changing membership.
* 668–740: exponential backoff is capped at 20 seconds. Search-base selection uses explicit base, cached RootDSE context, native DC lookup or domain APIs; relative bases append only without an explicit base. Search controls constrain domain scope and optionally request deleted objects or DACL/owner security descriptors. A requested attribute/control is not proof the principal could read every returned object's security data.
* 742–813: bags are reused; a faulted release disposes its connection. Dispose drains the ordinary bag only in this method, not the global-catalog bag. This is a source-level cleanup question, requiring an owned mock/disposable-server test before asserting observable leaked sockets. Whole-process exit and manager ownership are separate.
* 815–952: explicit server selection or multiple domain/DC discovery strategies. Some failures add a domain to a static exclusion set. LDAP connectivity failure can therefore affect later collection coverage within this process. SSL is tried first, then non-SSL unless ForceSSL is set. This is capability behavior, not an instruction to weaken transport protection.
* 954–987: LDAP v3, referral chasing disabled, five-minute connection timeout; SSL or configured DisableSigning disables LDAP signing/sealing, otherwise both enabled. DisableCertVerification installs an always-true certificate callback. Username/password, if supplied, become NetworkCredential; AuthType comes from configuration. Distinguish TLS channel confidentiality, server certificate validation, LDAP integrity/sealing and account authentication. Merely using a secure port does not establish all four.
* 1000–1064: synchronous Bind first; invalid credentials/inappropriate authentication raise a specific exception. RootDSE search then validates useful data with timeout retries. A successful bind without returned entries is rejected as NoLdapData, not accepted as coverage. Native/.NET behavior remains outside this source boundary.
* 1072–1095: prechecks test LDAP or GC ports, then call connection creation. Both branches pass true as the globalCatalog argument, including the ordinary LDAP branch. This is a precise source discrepancy requiring a controlled branch test and version comparison, not a verified production failure. No actual port checks ran.
* 1097–1122: metrics increment before a timed request, decrement after its await; the timeout callback ignores its cancellation token and passes a padded request timeout. The post-request decrement is not in finally. Exceptional completion could skew in-flight metrics; test fault paths before interpreting operational counts.

`LdapConfig.cs` 1–57 complete: null explicit credentials/server, ForceSSL=false, DisableSigning=false, DisableCertVerification=false, Kerberos AuthType, MaxConcurrentQueries=15; LDAP ports respect custom overrides, GC uses fixed 3268/3269. ToString includes username and masks password with its length. These are this class's defaults, not an assertion about final CLI-resolved configuration or every edition.

`LdapConnectionWrapper.cs` 1–97 complete: obtains server/context from RootDSE, caches the three naming contexts, and identifies equality through a string initialized with new Guid(), rather than Guid.NewGuid(). Equal-default wrapper identifiers are a source observation; their effect on any consumer requires a traced use, not an assumed graph-ID collision. This field is not the AD object's SID/GUID.

`AdaptiveTimeout.cs` 1–391 complete: 15–65 validates configuration and initializes the sampler; 72–253 wraps sync/async/native/RPC operations and records outcomes. 256–284 disposes the sampler and chooses max timeout until enough adaptive samples, then clamps mean plus seven standard deviations. The comments' statistical claims depend on assumptions and are not independently validated here. 286–349 resets sampling after spikes and optionally raises on excessive timeouts. 351–391 uses a compare/exchange loop for atomic decrement. Timeout result is a waiting-budget outcome, not proof remote work stopped.

`Timeout.cs` 1–179 complete: sync work runs in a task; async work is invoked and raced against Task.Delay. A linked token is cancelled after the race, with cancellation distinguished from timeout in returned failures. Cancellation is cooperative. Non-cancellation task exceptions propagate when awaited; there is no forced termination of non-cooperative work. Native/RPC wrappers translate result types.

`Extensions.cs` 1–233 complete: 21–40 materializes asynchronous streams in memory; 43–161 supplies enumerator helpers, some without token propagation. 164–210 encodes SID/GUID LDAP values and selects collection flags. 212–233 wraps .NET BeginSendRequest/EndSendRequest with FromAsync, request timeout and NoPartialResultSupport; it does not take an abort token or invoke Abort. Combined with the caller, abandoning a wait must not be reported as proven network-operation cancellation.

`test/unit/LdapConnectionPoolTest.cs` 1–45 complete: one exclusion early-exit test and one test expecting a non-excluded domain to attempt connection. The second contains a domain name and calls the real connection manager with only a logger mocked. **Not run**: test naming/mock presence alone does not make a test network-isolated. Neither test covers paging, certificate handling, disabled semaphore, GC disposal or the port-precheck discrepancy.

## Next controlled oracles

Before any test, choose a mockable transport seam or an isolated owned directory fixture. Assert exact called ports/globalCatalog flags; counts of acquired/released/disposed ordinary and GC wrappers; bounded retries under missing page controls; retained entries plus explicit error on later-page failure; and that request abort differs from returned timeout. Capture SDK/dependency pins and cleanup. These are proposed experiments, not receipts, and require no third-party directory access.
