# Cloud posture: collection, policy heuristic and effective permission

Prowler **5.45.0**, commit `bffc8844c1c9a3666e37a2ada4ee05f62e1446b0`, selected pinned source artifacts. Recursive tree receipt is names/metadata only. No Prowler package/provider was imported, no SDK/session/ambient credentials discovered, and no cloud account/API was used. A cloud posture check can find risky configurations; it is not automatically a complete IAM policy evaluator or an executed privilege validation.

An authorized cloud/security engineer supplies scoped account/region/resource identity and approved read permissions; collection returns observed configuration plus denied/missing/partial states, checks interpret them into statuses, and reports feed triage/retest. Effective permission additionally depends on principal/session, applicable policy types, conditions, explicit denials and organization/resource context. Preserve the difference between a broad-policy warning and proof that a specific action is currently permitted. No dangerous capability was exercised to infer the latter.

## Selected check and collection

Full files read:

* `prowler/providers/aws/services/iam/iam_client.py` 1–5 constructs IAM using the global provider **at module import**. Importing a check in an ordinary runtime is therefore not necessarily offline. Our fixture deliberately excludes this initialization.
* `.../iam_aws_attached_policy_no_administrative_privileges.py` 1–22 loops collected policies, chooses attached AWS-managed policies, creates a report initially PASS, and changes it to FAIL only when a present document satisfies check_admin_access. Missing policy document does not change that initial status in this body. Downstream failed-check annotations/model behavior must be traced before claiming final false-pass output.
* Its `.metadata.json` 1–44 declares critical severity, broad administrative-policy rationale and remediation suggestions. Severity/recommendation are metadata judgments; they do not mean an attack was executed or remediation is safe for this account. No fixer was downloaded/invoked for this check and no cloud mutation was authorized.
* `prowler/providers/aws/lib/service/service.py` 1–126 copies provider account/partition/resources/config/session, creates regional/default clients and a ten-worker ThreadPoolExecutor. It submits one future per item, awaits completion and suppresses exceptions at that layer on the assumption called functions handle them. Ten workers bounds simultaneous workers, not queue size, total API calls or memory. Static failed-check state can record check/ARN pairs, but this file alone does not prove every denied call records them. No explicit executor shutdown appears in this file; owner cleanup remains a dependency.

IAM collector newly closed ranges 201–739 and 851–1139 show inconsistent failure representations. Password-policy NoSuchEntity installs an explicit default, AccessDenied leaves None. Login-profile exceptions leave console_access false, so denied collection can share a representation with no profile. Several attached/inline-policy methods retain model defaults or partial lists after logged errors. `_list_tags` accesses error.response even in an Exception catch, which may itself fail for non-SDK exceptions; source-only. User last-accessed polling loops without an explicit attempt/delay bound here, while role polling has 60 retries and a sleep; no polling was exercised. Access-key metadata replaces rather than appends its list on each page. These concern collection completeness and lifecycle, not credential acquisition or live permission findings.

The complete policy module contains different heuristics with different semantics: `get_effective_actions` subtracts expanded Deny actions but does not evaluate resources/conditions/request context; `check_full_service_access` additionally seeks Resource:* Allows, still without full authorization evaluation. `is_policy_public` explicitly omits Deny reasoning, recognizes selected principal/condition/IP patterns and mutates condition dictionaries while normalizing keys. Trusted IP checking compares literal entries, not general CIDR containment. The reviewed two-pointer wildcard matcher avoids translating each wildcard into a regex; its comment's historical timing/impact claims were not independently reproduced. The separate marketplace helper intentionally ignores conditional Deny for global cancellation and treats conditional Allow as potential access. Do not replace these distinct meanings with one claim of effective cloud permissions.

Metadata models validate names, category/severity/taxonomy/remediation shape, with explicit relaxations for external-tool wrappers; such validation does not establish collection completeness or observation accuracy. AWS report dataclasses copy metadata/resource values and expose plain status fields. Provider-specific report fallbacks can synthesize names/locations. Image report `image_digest` is populated from `PkgID` in this model, so downstream consumers must not assume it is an OCI manifest digest without following provider output. IaC line ranges and LLM text similarly derive from supplied result fields, not independent verification.

Provider resolution gives built-ins precedence over identically named entry points, imports selected modules, enforces external Provider subclass shape and caches entry-point hits/misses. Class resolution avoiding global-provider initialization is not equivalent to sandboxing imported plugin code. The global singleton can be reused for the same class despite new CLI arguments; caller lifecycle determines whether this matters. Default external argument adapters omit provider_uid and require overrides when it defines scope. These are integration prerequisites and source-only questions, not demonstrated scope bypasses. Final output normalizes account/resource identity with provider-specific fallbacks; retain the raw identity and collection errors when comparing reports.
