# Workflow, tools and the evidence they establish

Research checkpoint, 2026-10-17. The category descriptions are practical synthesis; linked maintainers document representative capabilities. These are examples, not purchase recommendations. Code-review coverage is separately recorded in `queue.json`.

## First separate the nouns

**HTTP, TLS, LDAP, SMB and Kerberos** are protocols. **Burp** is a proprietary application suite. **mitmproxy** is an intercepting proxy tool with an addon framework. **Impacket** is a protocol library plus example clients. **Metasploit Framework** is a module/execution framework; **Metasploit Pro** is a commercial product. **Kali** is a Linux distribution packaging many independent projects. **A Burp extension** runs within a host product and inherits access to its traffic/process. **A VPN service** supplies operated infrastructure as well as client software. None of these nouns means “authorized assessment.”

The durable flow is scope/access → reachable assets → application/protocol observations → hypotheses → controlled validation → reviewed finding → remediation → retest. There are feedback loops: source review can explain a packet, a graph can suggest a role pair, and a failed replay can expose stale session state. Raw observations should survive every transition.

| Workstation distributions: Kali; ordinary Linux/Windows/macOS with selected tools | Package compatible utilities for an assessor. Assessor/lab engineer defines synthetic data, allowed network and expected outcomes first. | Pinned images/builds, fixtures, routes and test identities → receipts, reset state and logs. | Containers share a kernel; privileged/host networking weakens isolation. Snapshots can retain credentials or stale time. Reaching a fixture proves only that configured path. Pin hashes, restrict egress externally, record reset and cleanup. This is proposed lab design, not a run already performed. |

| Discovery and service enumeration: Nmap | Determine responsive hosts/ports and characterize services from an approved vantage. Network assessor needs exact assets, permitted methods, rate/time limits and sometimes raw-socket privileges. | Explicit target set and probe settings → port states, reasons, service hypotheses and structured output. A version fingerprint is not proof that a particular vulnerability is exploitable. |

Capture contents may include unrelated secrets; minimize by design. |

A compliance mapping is not certification; config risk is not an executed privilege path. Record denied APIs and unvisited regions, not just successful checks. An image scan misses deployed runtime permissions/secrets/network. IaC intent can differ from actual state. Retain image digest, DB version, ignored findings and unsupported content. |
| Mobile static/dynamic analysis: MobSF, Frida; reverse engineering tools | Inspect packaged apps and instrument their runtime on an owned emulator/test device. [MobSF project](https://github.com/MobSF/Mobile-Security-Framework-MobSF), [Frida docs](https://frida.re/docs/home/). | Static strings are not runtime proof. ## A synthetic application engagement

Proposed narrative, not executed: two fictional tenant accounts and seeded invoices run in a disposable local app. The assessor first records scope, fixture hashes, allowed operations and the oracle: A may read only A's invoice; B may read only B's. A client/proxy captures normal flows. A separate replay client changes only the synthetic invoice identifier, preserves the acting identity and records response bytes. The finding requires observing the other tenant's seeded content, not merely HTTP 200. Logs tie the response to server-side authorization behavior. Source analysis locates the missing tenant check. A patched build is retested with both legitimate and cross-tenant cases, plus expired identities. A report includes versions, exact evidence, tested matrix and missing cases. Packet evidence can explain connection failure, but encrypted packets alone cannot confirm invoice contents.

## A synthetic identity engagement

Proposed narrative: a fixture dataset states that fictional user Ada belongs to a Helpdesk group, and that group has one modeled right on a lab computer. A graph query suggests a path. The assessor checks which collector observations generated each edge, timestamps and denied sources, and whether the right's documented preconditions hold. An approved synthetic permission check can then test the specific capability. The path is recorded as modeled until validated; stale sessions are not silently carried forward. After removing the relationship in a fresh fixture, recollection and analysis must show whether the old edge is retired. Collection success, graph reachability and actual authorization are three distinct outcomes.

## Evidence handoffs that often break

Keep scope revision, time, environment/build, source tool version, rules/templates, vantage point, identity/role, raw input/output hashes, transformations, errors and oracle together. An adapter that retains only severity/title loses the basis for independent review. A report should say “not tested because API denied” rather than translate it to “passed.” Record secrets through safe references or redacted derivatives while keeping controlled original artifacts where authorized. Hashes detect byte changes; they do not prove who collected the bytes or whether the test was valid.
