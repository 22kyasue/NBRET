# From target expressions to scan evidence

Nmap maintains several different kinds of identity: the operator's target expression, a resolved numeric address, a reverse-DNS name, route/interface information and observed port/host state. These are not interchangeable evidence. This continuation follows the existing Nmap pin in [the catalog](catalog.md); [target expansion/exclusions](discovery-targets.md), [DNS](dns-flow.md) and [Nsock](nsock-flow.md) contain their canonical details. All observations here are source-only, dated2026-10-17. No scan or interface operation was run.

## Target insertion and state

`NewTargets.cc:1–149` and `NewTargets.h:1–107` are fully read. The NSE insertion queue deduplicates exact strings using a persistent history set, not normalized address identities. Repeated insertion returns1 even when no new queue item exists. The public insertion wrapper rejects post-scan additions and strings at least1024 bytes long; this file supplies no aggregate history/queue limit or engagement allowlist. Empty insertion returns the existing queue size. Successful insertion therefore means acceptance by this queue, not authorization, uniqueness of a resolved host or completed scanning.

Targeted caller reads, not full-file credit: `nse_nmaplib.cc:745–790` increments its reported count for each nonzero insertion result, so duplicate acceptance can be counted as an added argument. `targets.cc:330–400` consumes queued expressions after ordinary expression retrieval, and checks script enablement before doing so. Its ordinary max-IP predicate is before that later NSE queue branch; full expression expansion/exclusion callers must be reviewed before any global cap or scope conclusion. The assignment from a temporary read().c_str() into a std::string completes within the same full expression; this observation alone does not establish a dangling-pointer defect.

`Target.cc:1–556` and `Target.h:1–313` are fully read. Initialization distinguishes unknown address/connectivity/state from measured results. Destination reassignment clears both stored names before updating its numeric string and port-list identifier. PTR names are copied and characters outside the accepted printable set are replaced with '*'; the original operator target name is copied separately, and display prefers that target name over PTR. Sanitized/displayed names therefore do not preserve original DNS bytes or establish verified host identity. Numeric address formatting omits IPv6 zone presentation even though the stored sockaddr retains its fields; retain structured addressing evidence when scope IDs matter.

Host timeout accounting atTarget.cc:422–458 accumulates selected running intervals using supplied/gettimeofday time, and timedOut is a predicate using strict greater-than. Despite a nearby start-clock comment, this const predicate does not itself stop the clock. A zero configured host timeout disables that predicate. Timeout is a scheduling outcome rather than proof the host is absent. Final clock stopping and output remain caller questions.

Cleanup frees owned names, fingerprint results, early-service buffers and script results. NameIP's no-argument buffer is a mutable per-object allocation despite the comment calling it static; it is overwritten on reuse. MAC/address/interface setters store metadata, not proof of a successful send. FillEthNfo can open a cached Ethernet handle and checks transmit capability and Ethernet MAC prerequisites; it was not called. It assigns eth->ethsd only in the supplied-handle branch, leaving the opened-handle branch dependent on caller initialization/use. The direct raw-scan caller atscan_engine_raw.cc:1170–1215 supplies USI->ethsd, narrowing that question for this path. Other callers and netutil ownership remain unread.

## Raw scan continuation queue

Read together with the already completed [retry coordinator](discovery-timing.md). `probespec.h:1–117` and `scan_engine_connect.h:1–77` are now fully read: the former supplies the compact type/protocol/tagged-union representation used by raw and connect paths, while the latter only declares the connect send/select entry points. Neither declares an authorization policy. Full bodies and state annotations remain in their owning dossiers.

Completion update: `scan_engine_raw.cc:1–2202` is fully read. At81–382 the stored probe supplies protocol/ports/ICMP ID and TCP sequence correlation, with a mirrored, masked retry value and several compatibility interpretations of returning TCP fields. These are correlation checks, not authenticated origin. Locally observed outgoing packets are rejected using address/port/IP-ID comparisons. setIP reads the locally constructed packet; it must not be mislabeled a remotely exposed parser solely from its casts/assertions.

At385–849 host-discovery reception checks destination address, known outstanding host, protocol and matching probe fields. Quoted ICMP errors are matched to the embedded original addresses/headers; target-origin port/protocol-unreachable can establish HOST_UP while other unreachables remain HOST_UNKNOWN, and time-exceeded selects HOST_DOWN. Preserve the reason and responding address: these are interpretation policies, not universal physical host-availability truths. A successful host response destroys other outstanding probes through external update helpers. Captured time and loop-now have different uses; minimum2ms read waits and a200ms allowance mean the supplied deadline is not an exact immediate-return guarantee.

At851–939 capture opens on the first target's device with snaplen256 and a generated BPF filter. At most20 targets receive individual source-address filter terms; larger batches intentionally use broader capture predicates. ICMP is admitted for embedded error matching. Neighbor-discovery filter offsets explicitly assume no IPv6 extension headers. Capture filtering is therefore a collection-efficiency mechanism, with later matching, not an engagement authorization control or complete packet archive. Truncation can constrain later evidence/payload reuse.

At941–1431 ARP/ND/IP send helpers construct packets, update sent counters, call the underlying send function and queue one logical outstanding probe. ARP short-send is logged but the probe is still queued; IP send return values are ignored here. UDP can generate multiple payloads per destination within one logical probe. Optional source variants multiply actual transmissions, and the source explicitly says their batch bypasses per-probe delay/congestion assumptions. These capabilities were not exercised; packet-count and send-attempt counters must not be treated as remote receipt. Lower send helpers and scheduler enforcement remain open. IPv6 UDP's use of the tcp union member for dport is not by itself a wrong-port finding: targeted probespec.h:63–110 shows both corresponding structs start with u16 dport.

At1434–1595 ARP/ND responses may mark a known host up even with no outstanding probe; those cases do not count as a response within the current timeout window. Retried-probe timing association uses a heuristic offset to account for capture delay. ND MAC storage is conditional on the reply carrying that option. These distinctions matter when reconciling host count, response count and timing receipts.

At1598–2202 port reception matches known host/protocol/ports and applicable sequence data, maps scan-type-specific response/error combinations to OPEN/CLOSED/FILTERED/UNFILTERED, then records reason/TTL/third-party responder after the external state update. An ACK-scan RST means UNFILTERED here, not OPEN. Target-origin UDP port-unreachable means CLOSED, whereas an intermediary response may yield FILTERED. UDP payload bytes are copied into owned EarlySvcResponse storage for later service identification; this is an explicit cross-stage data flow, not service identity proof. The protocol-ICMP special case has static cross-call state and consumes current header/data/timestamp when completing its deferred update; lifetime and association need dependent caller review.

Targeted dependency reads (no full-file credit): tcpip.cc:1178–1290 and1330–1378 show readip_pcap(validate=true) invokes validatepkt. That validates TCP/UDP minimum headers and TCP options, contradicting a claim that every unchecked local memcpy in the raw receiver is directly reachable with a short TCP/UDP packet. SCTP and ICMP are not minimum-length checked in validatepkt's protocol switch, so their local copies still require the upstream accept_ip/read_reply_pcap and IP-helper chain before determining reachability or impact. readip_pcap also resets its returned length to captured length after validation had shortened it; full parser/trailer handling is next. No malformed packet or native parser was executed.

`scan_engine_raw.h:1–88` is fully read; it only declares send/capture/result entry points. The raw implementation is now complete above. Existing earlier credit already closes targets.cc and scan_engine.cc; their prior annotations must be reconciled rather than rereading or treating them as unread. In particular, targets.cc:452–520 supplies the later maximum-selection and exclusion check, narrowing the apparent cap bypass in next_expression alone. Actual netutil send/capture ownership and dependent parser enforcement remain next. Declarations and targeted snippets receive no full implementation credit.

`scan_engine.h:1–697` is fully read. Probe state distinguishes active, timed-out-but-retained, retransmitted, compacted bench and queued retries. A list size is not active-packet count. The two parallel retry vectors must remain aligned; late responses can match completed hosts retained for that purpose. Retry identity combines one ping bit with seven sequence bits, and ping sequence wraps at128. Base-port progression reduces nearby cross-phase ambiguity but is finite correlation state, not replay-resistant authentication. Host/group timing and rate gates are separate from the raw sender's packet multiplication. Declarations/comments describe contracts; the already credited implementation and timing helpers supply actual enforcement.

`tcpip.cc:1–1598` is fully read. At89–370 trace helpers increment raw counters before optional text formatting; tracer output is a formatted summary and counters are not delivered-packet acknowledgments. At374–429 sending dispatches by IP version and traces non-minus-one lower-layer results; the logical scan sender's pre-send counters are distinct. Fragmentation delegates to netutil. At432–1099 layered builders allocate owned packet buffers, calculate checksums, copy payloads and free intermediate transport buffers. They do not send by themselves. IPv4 ICMP/IGMP payloads are bounded to local1500-byte arrays; other builders depend on caller-validated lengths/options, with u16 payload parameters and protocol-length conversions. Deliberately nonstandard checksum/source/fragment options are source capabilities only; no such packet was built or transmitted.

At1101–1375 TCP option parsing advances only by validated option lengths, with EOL/NOP special cases. validatepkt delegates IP structural parsing, rejects noninitial IPv4 fragments and checks TCP/UDP headers; it does not validate every protocol or cryptographically authenticate responses. accept_ip checks captured minimum IPv4-header space and IP version only. This narrows the unresolved SCTP/ICMP local-copy path: accept_ip itself adds no transport minimum. read_reply_pcap and libnetutil IP parsing/length adjustment remain required before any native overread or reachable-impact conclusion. The final reset to caplen after validation's trimming is a source inconsistency to reconcile with downstream ip_get_data, not an established malformed-packet incident.

At1378–1598 capture timestamps are platform-qualified; pcap statistics distinguish kernel drops from filtered receives. MAC inference requires matching source, Ethernet link data, nonzero MAC and directly connected target state. Next-hop resolution may consult cache or actively resolve the gateway/target MAC, so merely setting up a target is not necessarily passive if executed. route_dst receives the configured interface/source. recvtime performs one receive and can return0 on receive error as well as EOF/timeout, with a separate timeout flag; consumers must not interpret byte count alone as one outcome. TCP timestamp extraction delegates to TCPOptions and uses a found flag because zero timestamp values can be valid. No native helper was called.
