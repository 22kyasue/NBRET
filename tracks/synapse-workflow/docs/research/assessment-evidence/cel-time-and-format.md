## Time validation is path-specific

timestampOf41–44 expressly does not validate time.Time range. String.ConvertToType124–134 first checks the strict scan, then time.Parse, then min/max Unix seconds. Int timestamp conversion and arithmetic have their own previously traced bounds. Timestamp.ConvertToNative157–181 calls tpb.New/Any or string formatting without an explicit CheckValid here. Native adapter normalization of zero time and protobuf AsTime behavior are distinct from string-input validation. An assessment cannot describe all ingress paths as equivalent just because timestamp(string) is checked.

Timestamp strict scan72–128 checks byte widths/ranges, separators, fraction digits and offset shape; the reference regexp67–68 is not the execution-path validator. TestIsStrictRFC3339MatchesPattern509–553 compares the two on a finite table including lowercase separators and leap seconds. That is scan/reference agreement, not a test that time.Parse accepts every scan-accepted case. The real String conversion tests167–200 check accepted examples and exact rejection messages for selected loose forms. The valid list only rejects IsError; ordinary timestamp conversion test142–145 separately compares an exact instant. Calendar validity remains delegated to time.Parse. Preserve the extra validation stage before inferring acceptance from the scanner alone.

timeZone355–395 chooses time.LoadLocation when no colon exists, otherwise parses numeric hours/minutes with Atoi and range checks, computes sign and uses FixedZone. It is not the strictRFC3339 scanner. Its stated regex-shaped comment does not itself enforce width/sign syntax. Named-zone outcomes depend on available timezone data, so future runtime receipts would need that environment. Tests429–477 assert valid named/numeric output and explicit out-of-range rejections. They do not claim every spelling is canonical. No timezone requests or parsing were performed.

Timestamp.IsZeroValue206–209's comment says epoch0, but implementation uses time.Time.IsZero. timestamp_test.go316–323 explicitly requires Unix epoch0 not to count as zero. This is concrete contradictory documentation and positive authored evidence of intended distinction. Native serialization's omit-zero path uses reflected native zero values, a related but different contract. Timestamp string conversion187–191 preserves RFC3339Nano/local offset while human Format257–259 forces UTC; neither should be silently substituted for a canonical evidence schema.

Duration operators55–73/148–176 and Timestamp.Subtract227–245 call the checked arithmetic helpers already reviewed and propagate errors. duration_test.go33–111/timestamp_test.go55–250 actually assert expected normal values and overflow errors, including nanosecond carries. Duration.ConvertToType122–133 produces integer nanoseconds but string seconds via floating-point Seconds/FormatFloat; hours/minutes/seconds getters193–218 convert floating-point totals to Int, while milliseconds uses integer Milliseconds220–227. A precise evidence claim should state units and any text precision rather than assuming integer round-trip from every string. Tests191–210 assert exact ordinary units; boundary-wide lossless round-trip is not established. No loss-of-precision sample was generated.

## Missing, null, unknown and printable are separate

Optional35–55 stores a reference; HasValue means non-nil ref.Val, so OptionalOf(NullValue) is conceptually distinct from OptionalNone. Optional conversion58–66 checks presence before even the *Optional identity case; absent optionals error, present values delegate native conversion. Equal80–92 delegates wrapped equality, preserving its possible nonboolean outcome. Tests25–187 assert present/absent, nested ordinary equality, exact Get and native identity/value behavior, but do not exhaust wrapped error/unknown cases. The previously read literal optional path unwraps after its first error/unknown check; binding provenance remains relevant to nested outcomes.

Null.ConvertToNative44–87 deliberately returns nil,nil for supported protobuf pointer/wrapper destinations, while rejecting JSON list/struct destinations. This matches the registry's explicit nil-conversion handling read earlier. Null.Value117–120 returns the protobuf null enum, not Go nil. Optional.Value116–122 drops the optional wrapper and returns underlying native Value or nil. A memory/evidence exporter that stores only Value loses some type/presence distinctions unless it records them separately. These are representation facts, not a demonstrated leak or incorrect policy result. null_test.go31–100 checks expected nil/protobuf values and error strings; its subtest-return92 does not skip later table rows, unlike the native conversion whole-test return.

Format15–20 explicitly says human consumption, ignored errors and unstable output. Its fallback23–42 uses formatting for opaque/error/unknown objects; list/map/optional/native protobuf formatters retain actual values. Sorted formatting in selected implementations does not override the public instability contract or constitute redaction. Persisted executable evidence needs a typed/versioned schema, not a human display string used as an assumed canonical hash key.
