## Execution evidence versus defensive evidence

Default logger 5–26 writes timestamp, technique/test identity, host/user/IP, PID and exit code. It omits the command, output, timeout and detector state despite receiving some of those inputs. Attire logger 69–145 retains command, output, exit and timeout, but that remains runner-produced execution evidence. Its final write at 147–187 merges compatible existing procedures; it is not an append-only forensic journal. Syslog and Windows-event loggers send runner records; their presence does not prove a security product observed the behavior through its normal data source.

A useful detection receipt must separately link the test's exact identity/inputs and execution interval to raw defensive telemetry, matched rule/version, alert, triage decision, containment and recovery. A runner-generated event shipped into the SIEM is not equivalent to native endpoint/identity telemetry detecting the activity. A nonzero command result may still have changed state; a zero result may not have produced the intended effect.

## Consequence for trustworthy claims

An assessment should say “dispatcher invoked; exit X; timeout Y; intended effect independently observed Z; cleanup verified against baseline W.” Collapsing those fields into “test passed” hides different failure modes. The runner is useful for repeatable execution, while a separate defender-side oracle is needed for detection coverage and an environment-state oracle for cleanup.
