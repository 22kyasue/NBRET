## Detector oracle and evaluator meaning

Complete `detectors/promptinject.py` 23–44 searches each latest output for a case-insensitive expected substring. Missing output/text becomes None; absent trigger metadata returns an empty score list. A refusal quoting the trigger can score a hit. A consequential unauthorized tool call without that string can score no hit. Those are limits of this chosen text predicate, not proof the detector is broken for its intended task.

Complete `detectors/base.py` contrasts other semantics: HFDetector 156–194 preserves None positions and converts classifier confidence; graceful failure returns unscored results. StringDetector 220–272 optionally normalizes Unicode. TriggerListDetector 280–304 returns None for missing trigger metadata rather than an empty list. These conventions are not identical; consumers must inspect the actual detector.

Evaluator `_evaluate_one_detector` 63–251 explicitly counts None separately from evaluated outputs and records per-intent totals and hit logs. It iterates score lists, assuming positional alignment with latest outputs; it does not establish that every output received a score. ThresholdEvaluator 533–543 passes values strictly below the threshold; zero tolerance passes exactly zero. Confidence intervals quantify a configured detector/sample model, not uncertainty about all undiscovered vulnerabilities or truth of the oracle.

The evidence chain therefore ends at “this response matched this predicate under these prompts/settings.” A whole-agent security claim additionally needs the tool call, affected resource, identity, authorization rule and independently observed effect. Public benchmark-like prompt text cannot supply those facts by itself.
