## Registry creation and state ownership

NewRegistry105–114 builds default proto registry then registers supplied items. NewProtoRegistry152–184 registers core types/well-known descriptors before options. ComposeTypes202–219 mutates a supplied registry in place only when provider and adapter are the exact same Registry; otherwise it constructs a new registry and stores fallback provider/adapter references. Local registered information takes precedence; delegation is retained for misses. This is composition, not tenant isolation or an independent schema snapshot.

Copy222–238 marks original and copy shared and shares maps, descriptors, provider/adapter references. ensureMutable240–248 clones the maps and copies pb database on a later mutation. The copied map values still reference existing type/descriptor objects; no deep-copy guarantee for arbitrary custom descriptors follows. JSON toggle256–270 builds/re-registers into a new database and assigns it after successful registration, rather than modifying the old database in place. RegisterDescriptor468–475 and RegisterMessage478–485 first mutate/register database then register all types; RegisterType496–529 and registerTypeItems809–830 proceed item by item and can return after earlier successful items. Failed registration is not established transactional rollback.

A subtle option contract deserves a precise boundary: RegistryOption returns a possibly replacement Registry pointer. NewProtoRegistry178 assigns that returned pointer, whereas registerTypeItem847–849 discards it and retains only error. Thus options that replace the registry have different handling when passed to NewRegistry through registerTypeItems versus directly to NewProtoRegistry. Existing built-in JSONFieldNames/ProtoTypeDefs/Types options return the supplied registry, so that difference alone does not show failure for those options. No replacement option or altered result was constructed.

## Lookup, object construction and adaptation

FindStructFieldNames319–338 chooses custom descriptor, protobuf field map, then fallback; protobuf names are collected in map iteration order, and prompt rendering sorts later. FindStructFieldType342–363 can return a custom descriptor's FieldType pointer directly, or construct protobuf getter/presence closures and JSON-name marker. Legacy FindFieldType289–315 converts CEL field types to protobuf type metadata; conversion errors become (nil,false). That compatibility route can therefore report not-found for an existing unrepresentable custom field; test2547–2561 explicitly expects this behavior. Do not translate that Boolean alone into proven field absence.

NewValue441–465 delegates custom types or creates a fresh protobuf message, validates every field name, converts/sets fields and returns an Err on failure. Partially populated local messages are not returned on these error branches. msgSetField912–952 builds list/map fields separately and sets the parent only after helper success; scalar nil conversion omits the field943–945. List helper954–972 skips nil element conversions962–964, and map helper974–999 skips nil values989–991. List Size is trusted as Int; map iteration stops whenever HasNext is not True without separately returning its unknown/error. A custom malformed iterator could therefore require extra handling (source inference); neither malformed object nor actual caller impact was demonstrated. Ordinary built-in iterator behavior still needs its implementation reviewed.

NativeToValue568–777 passes existing ref.Val through unchanged596–597; wraps byte slices666–667, uses specialized list/map adapters669–679, unwraps Any via UnmarshalNew685–689, and delegates unknown protobuf/native types to retained adapter where configured. Unsupported conversions return Err rather than an allow Boolean. Pointer scalar branches only dereference nonnil pointers; reflection/custom descriptor paths differ, so do not infer one uniform nil policy from a single case. No deep evidence snapshot is taken at this entry. Protobuf durations/timestamps use AsDuration/AsTime618–625; validation of raw protobuf validity is not explicitly called here. Exact protobuf helpers/actual caller constraints remain dependencies before any invalid-input impact claim.
