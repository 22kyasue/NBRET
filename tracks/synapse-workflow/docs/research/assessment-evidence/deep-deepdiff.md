## What this establishes, and what it does not

The source establishes that state-oracle output depends on version, options, object extraction, exclusions, traversal and report conversion. A trustworthy executable claim should therefore retain the exact comparison dependency and distinguish **allowed differences**, **ignored bookkeeping**, **unexpected differences**, and **unprocessed state**. Application predicates that require exact categories may reject a representation change even when the intended workflow remains the same; that is a plausible compatibility risk, not a demonstrated false verdict in AgentDojo.

Positive boundaries matter: default `max_diffs=None` contradicts an assertion that these application calls normally truncate at an arbitrary fixed diff count. The default ordered branch contradicts attributing every unordered-pair heuristic to these tasks. Explicit `unprocessed` reporting contradicts a blanket claim that extraction failure always means equality. Exact caller options and result handling must be traced before claiming security impact.

Next source questions: complete `helper.py` object extraction/path normalization; `model.py` category conversion/path construction and mutual-add/remove merging; `serialization.py` default text-view dependencies; `DeepHash`, ordered-set and cache dependencies where actually reached; then authored tests for Pydantic models, excluded paths and oracle-relevant category changes. The smallest credible validation, if later needed, compares an independently specified benign state transition against the unchanged dependency and application predicate with exact versions. No fault or exploitation fixture is needed for this source checkpoint.
