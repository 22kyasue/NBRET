## Request, model, data and verdict

For the reviewed v1 path: `Server.Check` validates the protobuf request and calls server authorization → resolves the requested or current authorization model → builds a resolver chain → `CheckQuery.Execute` validates tuple/context inputs and installs a request-scoped datastore/type system → cached resolver delegates misses → local checker combines relationship rewrites and condition-filtered tuples → response/error and resource metrics return. An authorization model says what permissions mean. Relationship tuples describe facts used by that model. Neither is automatically a complete or correct specification of the application's business intent.

## Cache identity is necessary; freshness is additional

Complete `pkg/storage/cache.go` 305–356 builds typed keys from cache domain, store, object, relation, user and an invariant digest. The invariant includes store/model, sorted contextual tuples and request context. Complete `keys/xtypes.go` 17–81 sorts map fields, distinguishes values by type and uses an explicit stack; 83–97 includes tuple condition name/context. Complete `keys/build.go` 107–211 length-frames variable fields and distinguishes map, array, unset and null; 219–308 snapshots the bytes into a key and formats it. This avoids common ambiguous string-concatenation and omitted-identity errors.

However, the invariant is a **64-bit digest**, not an authenticity proof or mathematically collision-free encoding. Complete `keys/hash.go` 11–40, 60–71 uses per-process random-seeded xxhash, with random initialization failure causing panic. It is a performance cache design with collision mitigation, not a provenance signature. Comments saying distinct stores can never collide should not become a universal cryptographic claim. Complete `keys/pool.go` resets pooled objects; wrapper copying is explicitly a caller discipline. These are internal trusted APIs.

Complete `internal/graph/cached_resolver.go` 111–204 bypasses lookup at HIGHER_CONSISTENCY, accepts cached entries only when newer than the request's last invalidation time, clones responses and avoids storing errors/cycle-dependent outcomes. Successful higher-consistency work may still populate the cache. Defaults (10 seconds/10,000 entries in this resolver) are source defaults, not verified deployment settings.

Complete `internal/cachecontroller/cache_controller.go` is explicit about eventual consistency:

- **145–194:** a missing changelog entry starts asynchronous invalidation and returns zero time, allowing cache reuse while refresh is in progress; an existing entry returns the last known write timestamp and refreshes at a configured interval.
- **208–299:** per-store single-flight work reads a descending changelog with a one-second context; timeout returns without refreshing; read error invalidates iterator caches. The code reads `changes[0]` after a successful response, depending on the datastore's documented nonempty-or-error contract. Datastore implementations are an unreviewed boundary.
- **302–377:** updates changelog state and writes full-store or relation/user-scoped iterator invalidation markers. Invalidating an iterator and invalidating a cached verdict are different mechanisms; do not treat one marker as a universal revocation barrier.

This is an intentional consistency/performance trade-off, not by itself a security defect. The correct question is whether the application's revocation promise matches the selected consistency mode and storage behavior. A remediation retest must record when a relationship changed, which model and consistency mode were used, and whether the application actually enforced the returned result.

## Condition compilation and failed-state retention

Complete `internal/condition/condition.go` 28–42 constructs the CEL environment; 68–148 compiles declared parameter types and requires a boolean output; 153–195 converts declared context fields; 202–289 clones and merges supplied context maps in order, uses partial activation and reports missing parameters/cost; 292–336 adds cost/interrupt options and constructors. Combined with `eval/eval.go` 112–125, stored tuple context is passed after request context and wins overlapping keys. This is a trust/precedence rule that a claim must disclose; it is not an automatic verification that either context source is authoritative.

The complete file also exposes a concrete failure-state defect at **68–78**: Compile uses sync.Once, but `compileErr` is a local variable. A failed first compile consumes the once flag; a later call returns a new nil local error despite an uninitialized CEL program. [Actual component fixture](deep-openfga-condition-lab_test.go) and [receipt](deep-openfga-receipt-1792268820277.json) confirm first-error/second-nil, followed by a locally caught Evaluate panic. A separate valid true-expression control compiles twice and evaluates true. The panic was contained inside the test; no server or stored model was used. Public request reachability, model validation bypass or production availability impact is **not established**.

Complete `inline.go` 35–92 validates declared parameter types; 95–153 parses an inline expression, infers undeclared identifiers as strings, applies cost/interrupt controls and compiles; 155–239 walks identifiers while excluding comprehension-local bindings. Complete `errors.go` 10–61 distinguishes compilation/evaluation/parameter errors and wrapped causes. Parameter converters/custom types and the pinned CEL interpreter are remaining source boundaries; these complete wrappers do not constitute a full expression-language audit.

This suggests a narrowly falsifiable improvement: retain the compilation error as part of the compiled object's state and assert repeated failure returns the same error category without panicking. A fix that turns the second call into a clean false permission, or silently retries under different parameters, would fail the evidence-preservation goal. Whether this defect is operationally consequential requires following the validation and reuse callers, not assuming component reachability from a synthetic constructor.
