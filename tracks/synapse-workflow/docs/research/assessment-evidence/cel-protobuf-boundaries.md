## Registration and copies

pb.go99–159 initializes from shared default descriptions; Copy clones non-default file/type indexing and extension-map containers, retaining extension FieldDescription pointers. file.go66–76 copies type descriptions but shares native descriptors/enums. type.go86–106 shares field maps and stored zero messages, rebinds extension lookup to the copied database, and returns the internal selected field map. pb.go162–164 similarly exposes the file slice. These are specific ownership boundaries, not a demonstrated cross-customer leak. Callers must not treat this as a deep immutable customer schema snapshot.

pb.go168–209 first deduplicates by file path, then prefers a descriptor from protoregistry.GlobalFiles with that same path. It does not compare supplied descriptor content before returning a cached description. This deliberately addresses independent descriptor instances: pb_test.go142–183 explicitly reconstructs a descriptor set and asserts that the registered field can read the linked message's true boolean. The successful field read is a stronger oracle than registration returning nil. It does not test divergent schemas sharing a path. CollectFileDescriptorSet245–265 traverses imports separately; registration of a single descriptor does not itself traverse all imports. file_test.go164–198 explicitly registers every collected descriptor before asserting imported enum values.

Copy tests pb_test.go95–134 compare whole structures and require inequality after adding distinct types. That establishes the authored copy scenarios, but inequality alone does not prove every old field/extension reference remained independent. The earlier provider sibling-lookup assertions provide additional, narrower controls. No shared-map mutation experiment was performed.

## Field access and conversions

type.go43–67 builds proto and JSON-name indexes. FieldByName109–129 checks JSON names first when enabled, then proto names, then extensions; FieldMap101–106 exposes one selected index rather than their union. type_test.go57–87 and133–151 assert normal camelCase/proto-name behavior. The enum check84 uses AND between wrong number and wrong name, so either one alone can be wrong without that assertion failing; file_test.go148–160 separately asserts enum values. Neither observation proves a faulty enum implementation.

IsSet260–276 and GetFrom284–318 use descriptor identity for the fast path and a same-field-name lookup for other message descriptors. There is no explicit missing-field guard in those fallback branches. Protobuf reflection behavior and real caller reachability must be established before claiming a crash or authorization effect; no malformed or mismatched message was constructed. GetFrom returns an error containing the supplied non-protobuf value at284–288, an evidence/logging consideration only if a later caller records that error. Ordinary list/scalar/bytes and map wrappers retain native values; conversion is not established a confidential-data snapshot.

unwrap441–519 and unwrapDynamic524–609 handle Any, dynamic messages and well-known types; Any decoding recursively re-enters unwrapping and depends on protobuf type resolution. Typed duration/timestamp paths call AsDuration/AsTime without CheckValid in these functions. A local recursive-depth/validity bound is not visible here; dependency limits and actual accepted inputs remain separate questions. Invalid/empty wrappers, unspecified structpb.Value kind and nil wrappers have explicit null/nil behavior. type_test.go325–514 contains both positive and nil/empty examples, requiring the unwrapped flag and independently specified expected value (proto.Equal or reflect.DeepEqual). Benchmark516–562 discards all MaybeUnwrap outputs and errors: timing that loop is not an independent correctness result.

## Merge and equality are different claims

pb.go66–85 uses proto.Merge for identical descriptors, but marshals/unmarshals between distinct descriptors with the same full name. The latter calls default proto.Unmarshal rather than an explicitly merge-enabled UnmarshalOptions. Exact reset/merge semantics remain a protobuf dependency obligation. pb_test.go185–206 prepares seconds=123 and checks only that Merge returned no error; it never asserts the destination seconds or preservation of existing fields. TestMergeError208–215 does assert the exact wrong-type error. These oracles should not be conflated.

equal.go45–112 requires descriptor identity before comparing fields. The Any branch checks equal type URLs, then returns true immediately for byte-identical payloads72–75; it only decodes differing payloads77–86. Thus the explanatory comment about unpacking Any has an important fast-path qualification. Malformed-but-identical bytes are not decoded on that branch. For different bytes with unresolved types the code returns false, consistent with unequal-byte fallback but not evidence of successful semantic decoding. No malformed fixture was executed.

equalValue150–173 uses floating-point == (NaN unequal); list/map recursion preserves those semantics. equalUnknown176–201 first checks length and identical bytes, then groups encoded fields by number before DeepEqual, so cross-field-number ordering can be ignored while each number's concatenated bytes remain ordered. This is more precise than the top comment's simple byte-equality description. ConsumeField error/negative-length handling is not explicit in that grouping loop; valid protobuf unknown-field invariants and caller reachability must be read before claiming impact. isAny204–206 uses a full-name test before an Any concrete assertion65–67; custom message implementation compatibility is another unestablished input boundary.

equal_test.go27–355 does execute its Equal call for every table row and compares the boolean to a stated expected result. Cases include distinct types, scalar/list/map values, NaN, nested Any, unresolved type URLs and nils. Helpers357–397 propagate packing errors; misPackAny changes the type URL intentionally. This is meaningful authored coverage, but does not establish arbitrary descriptor implementations or malformed raw fields safe. BUILD.bazel35–53 includes all four test files, unlike the separate CEL macro-test build omission documented elsewhere. No build was run.

## Assessment implications and next obligations

An executable claim needs both the data-model identity and a postcondition: a successful conversion call is weaker than proving that the intended fields survived with the intended values. A source-backed report should record descriptor origin, global resolution, name mode, copy/borrowing assumptions, exact conversion path and the asserted output. Preserve separate statuses for source-read, authored assertion and runtime-verified.

Continue existing value/map/list/error implementations and exact protobuf reflection/marshal dependencies where they resolve real callers. Do not manufacture runtime impact from a public helper's possible custom-input failure. The previously flagged operation remains stopped and was not retried or reproduced.
