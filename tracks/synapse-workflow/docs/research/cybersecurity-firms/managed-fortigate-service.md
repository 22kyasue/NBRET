# Managed FortiGate: changes after approval, with explicit exclusions

Read 2026-10-17: all 16 extracted pages of the [26.1 FAQ](https://fortinetweb.s3.amazonaws.com/docs.fortinet.com/v2/attachments/75930522-294d-11f1-b31d-02356ffb40d9/Managed_FortiGate_Service-26.1-Frequently_Asked_Questions.pdf), March 2026. Public operating description, not an executed contract.

The remote service runs continuously but is **English-only**. Customers supply basic internet-connected configuration; entitlement is per FortiGate, including each cluster member. Break/fix support, onsite work, design, migrations and third-party configuration are excluded.

Customers retain local device writes; the service's FortiManager Cloud is customer-read-only. Configuration revision history supports reversion. Migrating an existing management instance is unsupported; onboarding replaces its cloud instance, a significant lifecycle boundary.

For SOCaaS alerts, analysis → proposed changes → customer authorization → implementation. Optional preauthorization permits changes with minor **or significant** impact without individual approval. FortiAI-Assist is named, but this FAQ does not disclose its model/decision mechanism.

High-priority targets are one-hour evaluation and two-hour implementation **start after approval**, not guaranteed completion/containment. Proposed firmware work and management-plane patches have separate provider responsibilities.

If no active entitlements remain, the management instance resets and data is erased under separate privacy terms. Exact retention, Japanese-language delivery and complete signed SLA/credits are not established. No service was activated.
