## Practical interpretation

The bridge supplies API tools to a customer-selected AI client. The client/model proposes the tool call; server registration limits which tools exist; API-key permissions limit what the remote service allows. An MCP read-only annotation and an external client's confirmation UI are distinct controls. This code does not reveal Companion's proprietary reasoning or prove a customer model's privacy policy.

Next discriminating reads: tool-description dependencies and third-party MCP dispatch validation/context cancellation; remote task semantics remain separate from this wrapper. Preserve this source-only state until receipts show actual execution.

## Endpoint mutation and schedule extension

The complete endpoint tool file now covers task list/detail, sensor-policy override/removal, endpoint inventory deletion/export, schedules and version-policy priority. These are separate operations; inventory deletion does not establish sensor uninstall, and export can create an artifact despite not changing protection. Writes use the already reviewed request/response helpers. No handler adds per-call human approval, polling, rollback or remote completion validation. The separately exposed task-get tool returns raw task status rather than enforcing a lifecycle.

Schedule create/update publish nested JSON schema and call validateScheduleItems before submission. The validator checks string patterns only when expected map/array/string assertions succeed; missing/wrong-shaped nested values are skipped by this helper. Dependency schema enforcement remains unread. Date patterns enforce digit shape, not a valid calendar date; duration optional groups allow a bare P by inspection. This is a bounded source observation, not a demonstrated remote acceptance or security bypass.
