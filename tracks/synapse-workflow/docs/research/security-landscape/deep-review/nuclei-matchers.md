## Complete source files

**matchers.go1–105** defines predicate type/condition/part, negative/name/status/size/word/regex/binary/DSL/XPath fields with template-facing descriptions. **107–148** defines LLM prompt, verdict options, model confidence threshold (default0), multiresponse Inputs, approximate token cap and allow-sole override. Comments say response values should not interpolate into instruction prompt; actual enforcement remains match_llm dependency. **150–183** holds encoding/case/match-all/internal fields and compiled state. **185–216** defines AND/OR and negation; negative predicates invert boolean and erase matched snippet. A positive negative-match output therefore may have no matched snippet.

**compile.go1–38** hex-decodes valid nonempty word values, computes type and structurally validates; invalid hex word silently remains unchanged, while invalid binary later errors. **40–80** defaults body part except DSL, caches/compiles regex and DSL, decodes binary; **82–108** validates condition/default OR and restricts case-insensitive to word, lowercasing configured words. Regex/DSL shared caches are compile performance/state dependencies, not false-positive adjudicators.

**validate.go1–85** reflects nonzero template fields, permits fields by matcher type, requires actual values, compiles XPath and invokes LLM-specific validation; **88–119** maps YAML field names/rejects unexpected fields. **121–151** disallows negative LLM matching because provider failures are represented as no-match, validates confidence0–1 and nonnegative token cap, requires at least two nonblank comparison inputs. This is an explicit error-to-finding guard, but does not prove model judgments are reliable or injection-resistant.

**match.go1–54** status/size membership, independent of AND within one predicate. **56–113** word rendering with scan options, substring matching/case handling/AND-OR and match-all; a render error returns false under AND, while OR proceeds with the unresolved original word after warning. **115–167** regex matching with literal-prefix optimization and first/all snippets. **169–198** binary substring predicates. **200–262** resolves dynamic DSL markers and evaluates with scan policy; resolution/parse errors false, runtime eval error false for AND or skipped for OR, nonboolean warning and continue. **264–344** parses HTML/XML (XML only when corpus starts with XML declaration) and XPath query results; parse errors false, query errors continue. **346–357** hides selected missing-parameter/argument DSL errors unless SHOW_DSL_ERRORS=true. These are predicate outcomes, not a complete execution-error ledger. Negative inversion is supplied by wrapper/caller, so error/no-match ambiguity must be traced in protocol dispatch rather than assumed safe universally.

**match_llm.go1–40** injects per-scan client, defines expected JSON and actual default confidence0.5 (correcting matcher field comment claiming default0). **42–111** builds prompt, calls Complete with context.Background, parses verdict, records model/prompt hash/verdict/confidence, compares Expect defaultyes and confidence. Failure/no client returns no-match with no audit; evidence string is returned without checking it is a quote present in corpus. Fixed JSON shape is not semantic grounding. Options are written into prompt; this function does not independently check verdict membership in Options beyond equality with Expect. Confidence bound is checked after Expect mismatch returns an audit; nonmatching audits can therefore contain out-of-contract confidence. These are source observations pending stub tests. **113–155** instructs model not to obey content and frames each response; **157–184** caps each response approximately and interpolates operator values. More than one input divides budget but rounds each to at least1; prompt instruction overhead is not counted here. context.Background means caller cancellation must be provided by injected client configuration, not propagated through this method.

**common/llm/llm.go1–22** defines provider-agnostic Complete interface; **24–39** truncates by bytes using4bytes/token approximation, no cap for nonpositive value. **41–80** frames response with nonce generated **once per process**, stable for cache effectiveness; nearby comment says per-call but implementation/OnceValue and later comment say process. Random generation fallback uses timestamp. Framing is a prompt-format defense, not demonstrated model resistance or permission enforcement. Prompt hashes vary across processes because boundary changes even for same corpus/question; raw prompt reproduction needs more than model/hash alone.

**llm_audit.go1–44** defines model, prompt hash, verdict/confidence audit and64-bit truncated SHA256 identifier. It deliberately excludes full target-containing prompt. No model revision, request ID, usage or cost fields in this struct; provider layer may have separate receipts. **protocols/llm.go1–62** whitelists target keys plus declared variables/constants/CLI vars into prompt values, resolving declared strings against target only. Actual trust of target keys depends on event creation and option maps. **64–124** resolves comparison-input placeholders against full event without recursive substitution of resulting response content. **126–166** binds client to compiled matchers/extractors and stores per-event audits keyed by matcher.Name (multiple unnamed matchers may collide; tests/callers needed). **168–195** looks up matching or sole audit and attaches to result events; **198–220** resolves inputs, calls audited classifier and wraps predicate result, delegating LLM extraction. This establishes a designed data/instruction separation, not proof of immunity to target-content instructions.
