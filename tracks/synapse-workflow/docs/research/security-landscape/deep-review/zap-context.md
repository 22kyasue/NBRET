## Caller distinction established

Reports0.43 `ExtensionReports.isIncluded` calls **Context.isIncluded**, not isInContext/isIncludedInScope. Thus context exclusion and inScope are not applied by this report filter. Installed component experiment confirms an included+excluded synthetic /private URL is not in context under isInContext yet passes report selection; toggling inScope false still passes. This is report population semantics, not proof active scans reach excluded URLs. NBRET's own report adapter is a separate path. Actual report artifact generation from such context selection remains untested.
