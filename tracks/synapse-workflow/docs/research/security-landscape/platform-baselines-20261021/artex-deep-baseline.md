## What autonomy actually means here

ARTEX has model-directed planning and execution. Goals, intents, facts, findings and hints are recorded in an exploration graph, linked to asset records; the engine wakes planning and dispatches workers. Its ordinary product is not a fixed scan sequence and does not require source code as its sole starting input. The frontend task API accepts free-form goal/description and task-associated settings, as documented in the prior capability map. Project architecture describes planner/worker/main-agent roles and the graph loop ([README.md:226–239](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/README.md#L226-L239), [README.md:269–290](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/README.md#L269-L290)).

That permits a URL-described investigation in principle; it does not establish reliable signup, inbox use, authenticated account separation, multistep browser control or unfamiliar-site discovery in the deployed configuration. Actual capability depends on provider, installed tools, agent bindings, visible skills/MCPs and runtime privileges. Source access can be supplied through files/workspace, but is not inherent URL-only knowledge. Accounts, credentials, authorization, mailbox access and MFA are separate input/access conditions, not inferred from an accessible page.

The Dockerfile installs Playwright MCP/CLI, Chromium and general command-line tools; this is a build recipe, not proof they are installed, connected to an agent or compatible with Kotaro's approved computeruse harness. It uses floating `@latest` packages, so the application commit does not freeze those dependencies ([Dockerfile:14–35](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/Dockerfile#L14-L35)). An ordinary browser tool could perform registration if configured; no dedicated successful self-signup/mail integration was established here. Reuse approved harness and dedicated inbox capabilities as narrow tools if native deployment lacks them; do not build a second browser engine first.

Hypotheses can be expressed as intents with supporting facts, hints and graph lineage. That is useful investigative state, not automatic scientific validation. The native fact insertion source requires a summary, permits absent evidence/confidence and stores a fact as confirmed; it is distinct from vulnerability finding admission. Keep prior research, target observations and independently checked effects separate. See `docs/research/security-landscape/artex-core-integration-20261021.md:5–19` and [agent/tools.go:1316–1344](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/agent/tools.go#L1316-L1344).

Norma offers persisted memory and relevance injection when explicitly configured. `RecordMemory` saves model-provided named content, and an enabled auto-injection path appends selected memories to later input ([memory/tools.go:51–88](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/memory/tools.go#L51-L88), [agentcore/agentcore.go:436–445](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/agentcore/agentcore.go#L436-L445)). This is storage/retrieval, not trained model improvement, truth checking or an independent evaluator. ARTEX worker options show transcript resume and compaction; that does not prove every SDK memory option is active. Freeze benchmark information boundaries: no hidden answers or scorer source in skills, memory, workspace or research retrieval.

## Permission and tool dispatch: concrete strengths and limits

Norma's dispatcher resolves the tool, validates schema unless the tool explicitly opts out, evaluates permissions, runs PreToolUse hooks, calls the tool with its execution context, caps text output and emits post-tool hooks ([harness/tools.go:28–119](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/harness/tools.go#L28-L119)). This supplies exact extension points for observation and admission; it is stronger evidence than a README safety label.

**Bypass does not bypass everything.** Norma first applies explicit tool deny rules and the tool's hard-denial verdict, then bypass mode allows the call; ARTEX's later pre-tool hooks still run. [permission/permission.go:83–105](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/permission/permission.go#L83-L105). This corrects any reading of bypass as “no checks at all.” Conversely, the matcher recognizes tool names and the name before parentheses, not fine-grained argument predicates ([permission/permission.go:138–150](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/permission/permission.go#L138-L150)); argument-sensitive policy needs an actual reviewed implementation elsewhere.

ARTEX's worker selects bypass and attaches its hooks ([agent/worker.go:429–473](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/agent/worker.go#L429-L473)). Its guard permits absent/disabled interception and unmatched calls without an active judge; configured deny/ask paths have real blocking branches. Tool-table resolution filters known disabled/unbound entries, but passes unknown tools and returns the input list on a database-read failure. Those existing source conclusions remain conditional on active configuration, not observed failures or escapes.

Norma Bash includes a small hard-denial safety floor and otherwise asks permission; bypass can allow that ask. Its own source calls the floor an incomplete sandbox ([tool/bash.go:17–25](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/bash.go#L17-L25), [tool/bash.go:61–71](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/bash.go#L61-L71)). File reads accept absolute paths; path resolution joins relative paths to the working directory without a containment check ([tool/files.go:16–54](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/files.go#L16-L54), [tool/helpers.go:89–95](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/helpers.go#L89-L95)). A workspace directory therefore is not an OS filesystem jail.

MCP stdio creates a subprocess, layers extra environment over the inherited environment, handshakes and explicitly kills/waits on close ([mcp/stdio.go:16–60](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/mcp/stdio.go#L16-L60)). This is an execution capability, not inert configuration. Custom command/Python/HTTP tools and engine-side enrichment must be covered alongside SDK calls. A recording proxy and model's promise do not establish mandatory destination control; the earlier enrichment and search paths include activity outside the target-recording proxy.

Borrow the existing tool/hook/visibility machinery, but avoid treating descriptions, prompts, schemas, language directives or optional LLM judgment as a deterministic whole-system boundary. Product configuration and enforceable isolation need distinct evidence.

| Process shutdown | Main signals a cancellation cause and gives HTTP shutdown five seconds; supervisor forwards TERM, waits, and restarts abnormal exits or update exit codes. [cmd/artex/main.go:100–169](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/cmd/artex/main.go#L100-L161); [start.sh:35–81](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/start.sh#L35-L81). | Application/supervisor/container state must be included in the run receipt. Stopping one process is not sufficient if a supervisor restarts it. |

Norma managed Bash has deliberate background behavior: a foreground timeout may become a background task rather than kill the command ([tool/bash.go:94–150](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/bash.go#L94-L150)). The task manager root context is independent of a turn; cancellation of a managed foreground wait does kill and await that task ([tool/task.go:169–187](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/task.go#L169-L187), [tool/task.go:382–405](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/task.go#L382-L405)). These distinctions matter when interpreting a timeout.

There is positive cleanup code: ARTEX worker defers Session.Close, which invokes task cleanup; cleanup kills managed tasks and closes interactive sessions. Unix helper sends a process-group kill; Windows helper invokes taskkill for the tree ([agent/worker.go:493–505](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/agent/worker.go#L493-L505), [agentcore/agentcore.go:334–342](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/agentcore/agentcore.go#L334-L342), [tool/task.go:513–525](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/task.go#L513-L525), [tool/task_unix.go:11–25](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/task_unix.go#L11-L25), [tool/task_windows.go:12–26](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/task_windows.go#L12-L26)). Kill status is assigned before the asynchronous watcher finishes; interactive wait cancellation can report timeout without itself closing the shell ([tool/task.go:313–327](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/task.go#L313-L327), [tool/shell_session.go:191–210](https://github.com/Autumn-27/Norma/blob/320ae32989da97dd91469bb89164cbfe87d83d5d/tool/shell_session.go#L191-L210)). This is source-level lifecycle behavior, not a demonstrated orphan or guarantee that every descendant exited.

The acceptance requirement should therefore name which control is being tested and independently observe listener/process/request/effect quiescence. Never reroute an action stopped by a security boundary into a different tool/session.

## Evidence and reporting: reuse the native lifecycle

ARTEX has more than text findings. Its evidence store validates lowercase hash paths, verifies length and SHA-256, stages body writes, syncs and renames them, and validates existing blobs before reuse ([evidence/store.go:33–115](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/evidence/store.go#L33-L115)). Traffic preparation snapshots request/response bodies plus method, URL, status, headers, capture time and hashes; finding export freezes bindings/report versions in an evidence transaction and optionally copies bodies before responding ([evidence/store.go:118–179](https://github.com/jiwoochris/artex-global/blob/fdfb7a17b7da5e2de716c0e98475ec77a41c64c6/evidence/store.go#L118-L179)). Body integrity is a concrete native capability worth preserving.

This establishes captured-byte consistency, not principal identity, authorization, exploit consequence, completeness of capture or a repaired build. The API permits finding/binding edits and retest runs; retain versions and native labels. A research import must not manufacture target evidence. Reuse native traffic IDs, evidence/report versions and lineage, then attach independent engagement/account/build/generation/control/effect records where actually known. Keep the canonical NBRET reader as the client-facing result and import rather than overwrite uncertainty or retest history.

A full report mapping still needs to specify missing bodies, truncation, edited evidence, absent identity, inconclusive checks and unsupported non-HTTP claims. Freeze the ARTEX submission before reviewer control replays; later evidence must not be backfilled into the original discovery result.
