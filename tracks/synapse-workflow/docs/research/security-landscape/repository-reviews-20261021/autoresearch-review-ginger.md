## Decision and evidence limits

**Use autoresearch as a model for disciplined experiment iteration, not as an existing security research platform or a ready-made swarm runtime.** It gives an external coding agent a narrow editable training program, a repeated measurement, and instructions for preserving useful changes. ## What is actually in the repository

The complete tracked tree has ten files: `README.md`, `program.md`, `prepare.py`, `train.py`, `pyproject.toml`, `uv.lock`, `.python-version`, `.gitignore`, `analysis.ipynb`, and `progress.png`. There is no separate agent service, launcher, scheduler, peer-coordination protocol, security scanner, sandbox, inbox integration or benchmark custody service in this tree. The README tells the user to start an external coding agent and point it at `program.md`. Its opening story about enormous autonomous swarms is framing, not an implementation inventory. [README.md:5–17,42–50](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/README.md#L5-L50).

The native workload is **small language-model pretraining on one NVIDIA GPU**. `train.py` implements a GPT-like causal transformer with rotary positions, normalized query/key vectors, Flash Attention, optional value embeddings, squared-ReLU MLPs and residual scaling. It combines AdamW updates for embeddings/output/scalars with Muon-style updates for matrix groups. Default effective model configuration is built from depth 8, aspect ratio 64 and head dimension 128, producing width 512 and four heads; the dataclass's standalone defaults are not the actual final configuration. Default total batch is 524,288 tokens and device batch is 128 sequences of length 2,048, giving two accumulation microsteps. [train.py:32–121](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/train.py#L32-L121), [124–290](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/train.py#L124-L290), [297–426](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/train.py#L297-L426), [432–511](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/train.py#L432-L511).

There is no training checkpoint write or resume path in this training file. Every invocation seeds Torch/CUDA, constructs the model and initializes its weights again. What the keep/discard loop primarily preserves is a **code candidate**, not an incrementally trained model artifact. In-memory optimizer state exists during a run but is not saved by this script. [train.py:457–508](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/train.py#L457-L508), [610–630](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/train.py#L610-L630).

## The experiment loop, concretely

1. The human and agent agree a fresh run tag. The instructions ask for a new branch, reading the three core files, checking prepared data and creating a TSV ledger. Setup confirmation precedes the autonomous loop. These are instructions inside the inspected source, not actions taken in NBRET. [program.md:7–19](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md#L7-L19).
2. Run the unchanged training file first to establish a baseline. [program.md:39](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md#L39).
3. The agent proposes an experiment by editing `train.py`, commits it, invokes training with redirected output, and extracts validation loss and peak memory. There is no required structured hypothesis, predicted outcome, single-variable restriction or causal attribution record. [program.md:90–104](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md#L90-L104).
4. Append a TSV row containing short commit, loss, memory, status and description. The ledger is deliberately untracked and ignored. [program.md:64–87,102](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md#L64-L104), [.gitignore:22–23](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/.gitignore#L22-L23).
5. Retain an improving commit; reset the branch for an equal/worse result. Instructions also permit equal-performing simplifications, creating a judgment exception to the stricter numbered loop. A transfer should make that exception explicit in advance. [program.md:35–37](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md#L35-L37), [103–110](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md#L103-L110).
6. Continue until interrupted; use judgment to fix small crashes or abandon broken ideas. The prompt asks the external agent to kill runs exceeding ten minutes. No watchdog implementation is provided. [program.md:108–114](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md#L108-L114).

This is sequential greedy search around the current kept code, with occasional discretionary rewinding. It is not a supplied population search, multi-agent consensus process or guaranteed optimization algorithm. Git reset removes a rejected candidate from the current branch's direct history; a short hash in an untracked TSV does not by itself promise durable retention of that candidate's commit objects. `run.log` is overwritten by the next run. A long-lived research ledger should retain all candidate diffs, full commit IDs and logs separately.

The intended division is stated in [README.md:11–17](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/README.md#L11-L17) and [program.md:25–37](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md#L25-L37). It is useful experimental discipline, but not protection against an agent accidentally or deliberately changing the measurement contract. The README's suggestion to disable permissions is not adopted for our lab. [README.md:42–48](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/README.md#L42-L48).

Even with `prepare.py` unchanged, editable code imports its functions/constants and supplies the model, tokenizer and batch size. The evaluator calls `model(x, y, reduction='none')`; the model implementation defines the returned quantity. It could therefore cease to be genuine cross-entropy without changing evaluator source. The printed metric is also within editable `train.py`. This is a source-established trust boundary, **not evidence that any recorded upstream agent cheated**. A security scorer cannot accept an investigator-authored “success” function as independent confirmation. [prepare.py:343–365](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L343-L365), [train.py:268–290,610–630](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/train.py#L268-L290).

## Data, metric and comparison contract

Preparation downloads Parquet shards from the Hugging Face `karpathy/climbmix-400b-shuffle` dataset's `main` path. Default preparation requests ten training shards plus final shard 6542 for validation. Tokenizer training excludes that validation filename and consumes capped training text; it builds an 8,192-entry BPE vocabulary including four special tokens. The cache is shared under the user's home directory. Existing shard files are accepted by existence, not rehashed against an expected dataset manifest. Downloads use a temporary file and rename, retry up to five times and print aggregate readiness; individual failed results are not raised as an aggregate exception by `download_data`. Dataset content hashes/revisions are not frozen in this source. [prepare.py:30–45](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L30-L45), [57–113](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L57-L113), [125–203](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L125-L203), [371–389](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L371-L389).

The runtime loader excludes the validation shard from training and cycles deterministically over sorted files, packing documents into full sequence rows. It can crop a document when no document fits the remaining row space. Validation uses the pinned validation path and the same packing machinery. This establishes a filename-based train/validation split; it does not demonstrate semantic deduplication between shards. Tokenizer state is loaded from a pickle, so those cache bytes are part of trusted runtime input. [prepare.py:217–220](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L217-L220), [254–337](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L254-L337).

The objective `val_bpb` is validation **bits per byte**, lower being better. For each scored target token, the evaluator takes an unreduced loss in nats, excludes zero-byte special tokens, sums loss and token-byte weights, and returns `total_nats / (ln(2) × total_bytes)`. The byte lookup is constructed from each individually decoded token's UTF-8 string length; no independent audit of Unicode byte-weight fidelity was performed here. “Vocabulary-independent” is the intended normalization, not proof that changing tokenization preserves identical evaluated content. [prepare.py:184–195](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L184-L195), [343–365](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L343-L365).

Evaluation fixes sequence length 2,048 and targets 20,971,520 tokens. Actual steps are integer division by `batch_size × MAX_SEQ_LEN`; the evaluated amount can fall below that target when it is not divisible. Batch size remains candidate-controlled and influences packing. There is no guard here against zero evaluation steps for an excessively large batch, which would leave a zero denominator; practical GPU memory may prevent such a configuration first. This is a conditional code-path observation, not a reproduced failure. [prepare.py:30–32,352–365](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L352-L365).

## Failure, leakage and history semantics

**Failure reporting is coarse.** The training loop exits on NaN or last-microbatch training loss above 100; positive infinity also exceeds that threshold. It does not validate the final metric as finite before printing. The prompt treats missing grepped summary output as a crash, but that can also reflect truncation, incomplete execution, changed formatting or collection failure. Conversely, a summary-shaped string is not independently verified execution. Crash TSV rows use numeric zero, which would look better than every valid positive loss if downstream processing ignored status. No structured timeout, setup-failure, evaluator-failure, invalid-metric or incomplete-evidence schema is implemented. [train.py:546–572,610–630](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/train.py#L546-L630), [program.md:74–78,99–110](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md#L74-L110).

**Repeated selection can overfit the validation measurement.** The agent repeatedly sees scores from the same public shard and can inspect the full evaluation code/data path. It is a tuning set in the research loop, not an investigator-blind final holdout. No separate final test set, repeat-count policy, uncertainty interval, independent evaluator process or enforced prohibition on validation access is supplied. Fixed seeds help control one source of variation; they do not establish deterministic GPU execution or distinguish a lucky tiny gain from a robust gain. The provided progress image even labels a later kept change as a random-seed change. That image is illustrative upstream evidence, not an independently verified run receipt. [prepare.py:41–44,254–273,343–365](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/prepare.py#L254-L365), [train.py:457–459](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/train.py#L457-L459), [progress.png](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/progress.png).

**The chart is a selected view of experimentation.** `analysis.ipynb` loads the absent user-generated TSV, excludes crashes from its scatter population and plots discarded points only near/below baseline. Its headline counts all rows/keeps, while its running line follows kept rows. This is useful for visualizing progress, but the chart does not show the full failed-run cost or all bad outcomes. The tracked notebook has no saved outputs and there is no tracked `results.tsv`, so the supplied PNG's 83 trials/15 kept improvements cannot be reconstructed from this tree alone. No absence of upstream private records is claimed. [analysis.ipynb:19–51](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/analysis.ipynb#L19-L51), [87–144](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/analysis.ipynb#L87-L144).

## Transfer to Kotaro's proposed environment

The current question is how to improve **tool selection and actual discovery** within the broader security research lab, including a client-commerce-style owned target, with autonomous work inside an admitted scope. Starting access is a URL, followed by agent-discovered normal registration and a dedicated readable test inbox. A counted level-3 finding needs a demonstrated violation, retained evidence, affected conditions, business consequence, repair guidance and repeatable verification. No finding is required merely to complete an investigation. These are existing decisions, not capabilities delivered by autoresearch.

The October 18 [discovery decisions](../../../synapse/discovery-decisions.md) already settle adaptive investigation, one initial scope approval, conversational steering, evidence/review/retest, blind versus guided learning and measured improvement. The newer [decision reconciliation](../../../../../../docs/consolidation/decision-reconciliation-2026-10-21.md) carries them forward and adds the broader lab, bounded helpers, supplied/generated targets and URL-only registration/inbox clarification. This review maps autoresearch onto those requirements; it does not restart that architecture or re-ask settled preferences. Implementation choices still needing evidence include actual custody/runtime enforcement, available inbox resources and the first admitted scorer/target population.

| Autoresearch concept | Transferable security-learning form | Required change before adoption |
| --- | --- | --- |
| Human edits `program.md` | Human and agent record investigation hypotheses, allowed methods and learning questions | Freeze a versioned public run contract; record human hints and assistance |

### Hypotheses and helpers

Use a small public hypothesis record: question, rationale from observable behavior, proposed helper/tool change, predicted discriminating observation, budget, and decision rule. Human and agent may both originate hypotheses. Preserve the reconciliation's three kinds: a target hypothesis tests a particular security rule; a method hypothesis tests whether a strategy/helper improves investigation; a platform hypothesis tests an orchestration/evidence change under a separately versioned contract. Example methodological question: does a helper that preserves identity/session bindings improve reproducibility and reduce false authorization claims compared with the same tool without it? That is an experimental proposal, not an assertion that the target has an authorization flaw.

Agents may write parsing, replay, evidence-capture or comparison helpers inside their admitted workspace. Hash their source and inputs, record invoked commands and treat outputs as investigator-produced evidence. Validate helper correctness against explicit positive/negative controls. A helper may propose a new oracle, but cannot silently install it as the score authority. New dependencies or expanded tool/network rights require a platform admission change outside the candidate experiment.

### Supplied and generated targets; three distinct modes

| Mode | What the investigator may know | What a result supports |
| --- | --- | --- |
| Guided learning | Known issue, source, hints or worked explanation may be supplied | Learning and technique development on disclosed material |
| Familiar regression | Prior cases and expected outcomes are deliberately known | Whether a change preserves previously demonstrated capability |
| Held-out evaluation | Investigator cannot access target source/hidden labels/scorer details beyond the public contract | Performance on admitted unseen cases, with contamination and sample limits stated |

Owner-supplied targets can support any mode depending on access/custody. Agent-generated targets are useful for guided learning and regression, but an investigator who generated or read a target's weakness cannot later claim blindness to it. Separate chats or folders under one unrestricted identity are not a custody boundary. Fresh variants must be prepared and checked by an isolated preparer, with hidden data excluded from investigator files, prompts, search, memory and board messages. Public familiarity and model-training contamination remain possible even with correct local isolation.

URL-only means the investigator receives no convenience admin or pre-provisioned shopper accounts. A first-class experiment stage must discover registration, create an admitted test identity, receive the correct verification message and establish normal account capabilities. Scope must name permitted account counts, inbox recipient/domain, read-only versus send rights, transactions, external verification dependencies and cleanup. Bind inbox messages and browser state to run/identity IDs; keep unrelated mail and personal accounts unavailable. If registration/mail delivery fails, record an access/setup outcome rather than awarding a clean security result. Autoresearch supplies none of this integration.

### The effect oracle and level-3 evidence

The scorer must use independently obtained application observations, not an investigator's status field, quoted response or generated test's own success assertion. For an authorization claim, establish the acting identity, target object/tenant, expected policy, before/after state, prohibited consequence and allowed comparison flow. Include no-action/pre-existing-state controls, wrong-actor/object mutations, partial-error effects and stale evidence. A secure denial and an unreachable feature are different outcomes. Preserve replay conditions and evidence completeness; repair guidance remains a recommendation until an actual repaired build is tested.

Do not optimize finding count alone. Record independently confirmed unique findings, adjudicated false claims, inconclusive claims, evidence completeness, reproducibility, time/cost and exercised coverage. Seed recall is meaningful only for independently verified eligible planted faults; the total flaw count of an ordinary app is unknown. “Best run” cherry-picking and repeated tuning on final score feedback would recreate validation overfit. Use development targets for iterative feedback, a separate regression suite, and restricted held-out scoring for promotion decisions. Fix repeats and adjudication rules before viewing comparative outcomes.

### Admission and autonomy

Autonomy inside the admitted lab can avoid repeated per-action prompts, consistent with Kotaro's preference. The owner must first admit concrete target endpoints, allowed effect classes, comparison identities, inbox and bounded resources. Enforcement belongs at tool/network/resource boundaries with process supervision and effect reconciliation. The agent cannot earn a higher score by broadening its permissions or rewriting the contract. A proposed platform/scoring/permission change becomes a separately reviewed experiment with a new version and baseline.

The autoresearch “continue indefinitely” prompt should become bounded batches with automatic budget/expiry stops and resumable state. No fixed schedule is imposed on Kotaro; a per-run budget is still necessary for fair comparison and operational control. Verify workers and target effects have stopped instead of equating a timeout/cancel acknowledgement with quiescence.

## Prior NBRET evidence, contrary evidence and recommendation

Prior-coverage check: the track register was searched for `autoresearch evaluator benchmark experiment`, and `rg` found no earlier `autoresearch`/`karpathy` occurrence in the track docs at that check. This is a scoped search, not a claim about every ignored file or external session. Relevant existing study passages were opened, including the full draft [assessment framework](../../assessment-evidence/framework.md) and [AgentDojo's current-task scorer discussion](../../assessment-evidence/deep-agentdojo.md#default-suite-follow-up-what-the-current-task-actually-checks).

The register entry `ai-evaluation.audit-evaluator-before-tester` is **synthesis**, with an explicitly draft protocol. Its source, `framework.md:75–92`, requires mutation tests, no-action controls, error categories and test reachability checks. `ai-evaluation.agentdojo-usertask6-accepts-wrong-recipient` is **component-lab** evidence for one extracted task predicate: wrong recipient and pre-existing qualifying state were accepted. `deep-agentdojo.md:53–59` also contains contrary evidence: other task versions check recipients and the missing constraints do not invalidate the entire benchmark. Those facts motivate independent oracles; they do not demonstrate a bug in autoresearch's training results.

`framework.md:5–25` supports matched access/budget, held-out families, declared assistance and interpretable denominators. Its source is a proposed evaluation method, not observed security-discovery improvement. The autoresearch source supplies a counterweight to simplistic rejection: a compact candidate surface, fixed measurement intent, first baseline and logged discarded ideas are useful and make iteration easier to inspect. The insufficiency is in transferring those conveniences into **independent claims of security capability** without adding enforcement, custody and effect evidence.

Recommendation: borrow the loop and narrow candidate workspace, retain the existing NBRET evidence discipline, and build/admit the environment and scorer as separate fixed infrastructure before running a comparison. A simpler alternative is openly guided practice on the current known environment while custody/inbox decisions are unresolved; that supports learning without a held-out performance claim. This report does not select a final tool arm, benchmark app, mail provider or runtime.

Validation that would support transfer: after separate authorization/admission, demonstrate that helpers can change within candidate space while attempted scorer/permission changes are denied; independently validate the scorer's positive/negative/no-action controls; verify URL-only registration/inbox flows; run matched baseline/candidate trials on reset targets; retain all failures; and confirm promising improvements on fresh unseen variants. Failure of custody, effect validation, target reset or scope enforcement would invalidate the corresponding comparison even if a numeric score improved. No such validation was performed in this review.
